### Composition behaviour

- **Start surface.** The shell's `MaterialApp` home is the new `StartScreen`.
  It renders `appTitle` in the app bar, `startTitle`, `emptyDocuments`, and a
  `FilledButton` labelled `importAction`. Startup-recovery notices keep the
  T031 behavior and remain rendered from `StartupSweepNotice` values.
- **Production import seam.** `FeldexaApp` defaults to `createImportRuntime`
  and `openPdfrxPageRenderer`; the tests inject fake factories.
  `import_runtime.dart` selects the Android file only when `dart.library.io`
  is available; the default and `dart.library.js_interop` branches select the
  fail-closed file. `import_runtime_android.dart` creates one
  `AndroidOperationClient`, `AndroidImportClient` (real `DocumentImportPort`),
  and `AndroidStoreClient`; no simulated adapter is constructed.
- **Protected read-back.** The editor receives the verified `ImportedSource`
  and a closure bound to `source.documentId`. The Android runtime resolves it
  with `AndroidStoreClient.loadDocument(documentId)`, which validates the
  committed meta/revision against the head and invokes `store.readSource`
  (`contracts/platform-channel.md` §4). `PageView` receives only
  `source.sourceId` and the closure; no path or URI is involved.
- **Editor route.** `EditorScreen` builds `PageViewController.fromImportedSource`
  once, owns a `PageStripController` over the same viewer, and builds one
  `PageStripPage` per source page with the default `pending` analysis state.
  Pages named in `source.pageFailures` set `unreadable: true`. The strip and
  viewport are composed in the contract's §1 order with the T042 viewer
  expanded below the T043 strip.
- **Partial pages.** Each page is projected into `PageStateInput`; an
  import-unreadable page uses `failed` plus the `IMP-006` catalog key, while
  readable pages remain `pending`. `derivePageStates` returns a success with
  the catalog warning; the editor renders both warning sentences in a
  live-region banner. The T044 rule that the T040 1x1 placeholder is never
  exposed as a real display size is preserved.
- **Failure surface.** Rejections render only `message` and `recovery` from
  `ImportFailurePresentation`. Cancellation is silent. The start surface's
  composition-failure guard uses the existing mapper's unknown-cause text; it
  never claims password protection or success. The create-document gate is
  invoked only after `pickAndImport` returns a verified source; no second
  document is written by T148.
- **Privacy.** The UI reads only the verified source metadata, page geometry,
  page failures, the store-returned bytes, and catalog strings. It logs
  nothing and renders no code, machine key, path, URI, display name, or page
  content in the new surfaces.
