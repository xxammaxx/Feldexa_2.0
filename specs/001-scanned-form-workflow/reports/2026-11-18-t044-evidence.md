### Page-state derivation

`derivePageStates` accepts one `PageStateInput` per page and sorts by index; it
requires a non-empty, unique, contiguous `0 … n-1` set. For each page:

| Input | Derived state |
| --- | --- |
| `analysis` pending, running, complete | readable; phase `pending`, `analyzing`, `ready`; display size exposed; `statusLabel` null |
| `analysis` failed with a non-`IMP-006` key | readable; phase `failed`; display size exposed; `statusLabel` is `AppLocalizations.rec002(pageNumber)` |
| `unreadable == true` | unreadable; display size `null`; `statusLabel` is `AppLocalizations.statusUnreadable` |
| `analysis` failed with `messageKey IMP-006` | unreadable; display size `null`; `statusLabel` is `AppLocalizations.statusUnreadable` |

The 1-based `pageNumber` is `pageIndex + 1`. The unreadable page numbers are
collected in ascending order, and both the page list and the affected-page
lists are unmodifiable.

`PageStateInput` deliberately carries no document id, title, display name,
path, URI, or page content. It validates the index, the failure-key pairing,
the catalog-key shape (so a path-like string cannot enter the state), and the
display size. Error messages are fixed strings and never echo the rejected
value; a test passes a URI-shaped failure key and asserts that neither the URI
nor its path appears in the error.

### The 1x1 placeholder decision

T039 reports null geometry for a page whose structure could not be read, and
T040 persists that page with a deterministic 1x1 pt box, `unreadable = true`,
`analysis: failed`, and an `IMP-006` `PageFailure`. The placeholder is not the
original page geometry.

T044 treats the page as unreadable from its flags, not from its size. Whenever
a page is unreadable, `PageState.displaySize` is `null` regardless of the
reported box, so the 1x1 placeholder can never become a thumbnail, layout, or
viewer size. The input still tolerates the placeholder, and the test parses the
exact persisted JSON shape to prove that the canonical 1x1 value is suppressed.
A readable page that reports 1x1 is treated as reporting 1x1, because this
projection never infers unreadability from a size alone; the import path marks
unreadability explicitly.

### The IMP-006 warning

A document with at least one readable and at least one unreadable page returns
`PageStateSuccess` with `warning != null`. The warning contains only:

- `message`: `AppLocalizations.imp006(affected.join(', '))`, for example the
  catalog sentence with `2, 4`;
- `recovery`: `AppLocalizations.imp006Recovery`;
- `pageNumbers`: the affected 1-based numbers, ascending.

The message already contains the catalog statement that exporting the complete
document is affected. `PageStateWarning.affectsFullExport` is always true and
`PageStateSuccess.isFullExportAffected` mirrors it; neither adds text. Tests
assert that message and recovery contain no catalog code, path, URI, PDF name,
or slash, and that the message equals the committed `AppLocalizations` value.

A fully readable document returns `PageStateSuccess` with `warning == null`,
`isFullyReadable == true`, and no affected pages.

### Fully unreadable input

A document with no readable page returns `PageStateFullyUnreadable`, not a
success and not an `IMP-006` warning. The result exposes every page as
unreadable and non-renderable. This state is not reachable through a successful
import because the import path rejects an all-unreadable source; it exists so
the derivation is total and cannot present such a source as a document.
Callers are documented not to create, present, or continue a document from it.

### Accessibility and page-strip data

Each `PageState` exposes `pageNumber`, `isUnreadable`, `isUsable`,
`displaySize`, and a German `statusLabel` where the catalog defines one. The
strip can combine `statusLabel` with
`AppLocalizations.a11yPageNavigation(page, count)` for a semantic hint. The
readable phases have no page-level status row in the catalog, so their label is
`null` rather than an invented sentence. The state is data only; no widget,
style, color, or icon is created here.
