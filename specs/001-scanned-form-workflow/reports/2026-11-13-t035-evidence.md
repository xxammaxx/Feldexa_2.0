## 5. Quality-review finding and correction

### 5.1 Finding

The review of exact candidate `3f2ed3e` found that §6.4's decision list required
only `R_pooled ≥ 0.80` and `U_pooled ≥ 0.80`, with a disclosure clause if a form
was below 80%. That permitted a `PASS` while an individual form failed the
80% target, because the disclosure did not change the decision. The finding is
valid if SC-003 and D-18 require a per-form comparison.

### 5.2 Normative verification

| Source | Normative text | Consequence |
| --- | --- | --- |
| `spec.md` SC-003 | "Manual placement work drops by at least 80% relative to fully manual placement, measured as the share of **a form's fields** that need no manual add, move, resize, or type change after the user's review." | The 80% field-share measure is stated for a form, not for a corpus average. |
| `research.md` D-18 | "**for each corpus form**, record the number of fields a reference operator must add/move/resize/reclassify after detection; compare against fully manual placement with the same operator and tool. Reduction = 1 − (manual actions after detection / fully manual actions)." | The reduction is computed and compared for each form. |
| `v1.0.0` §6.4 (candidate `3f2ed3e`) | Required `R_pooled ≥ 0.80` and `U_pooled ≥ 0.80`; a below-80% form was only disclosed. | A below-80% form could not by itself prevent `PASS`; this conflicts with the two sources above. |
| `v1.1.0` §6.4 (this candidate) | Requires `R_f ≥ 0.80` and `U_f ≥ 0.80` for every form; pooled values are context only; any single failing form makes SC-003 `FAIL` when the measurement is valid. | The conflict is removed; no pooled or averaged value can substitute for a per-form result. |

No normative source defines a pooled corpus threshold for SC-003. The finding
is therefore a genuine conflict, not a documentation preference. The correction
does not change the 80% threshold, the D-18 formula, or any measurement rule; it
applies the existing threshold and formula at the level the sources state.

### 5.4 Correction applied

- Protocol version raised to `manual-baseline-protocol.v1.1.0`; `v1.0.0` is
  retained in history and was never used for a scored run.
- §1 states the per-form reading directly from SC-003 and D-18.
- §6.2 is now "Pooled context values (not acceptance)"; pooled values are
  descriptive only.
- §6.3 compares each form's unrounded `R_f` and `U_f` with 0.80 and reports the
  per-form distribution.
- §6.4 requires `R_f ≥ 0.80` and `U_f ≥ 0.80` for every form; any single failing
  form makes SC-003 `FAIL` when the measurement is valid, and `PARTIAL`/`FAIL`
  when evidence is incomplete. Averaging, pooling, weighting, trimming,
  exclusion, and per-form selection are prohibited as substitutes.
- §7.2 adds a per-form SC-003 verdict column; §7.3 is a per-form decision summary
  with pooled values explicitly marked "Not a decision".
- §8 prohibits using pooled or averaged values as the SC-003 decision while a
  form is below 80%.
- §9 adds the per-form checklist items; §10 records the stricter per-form
  limitation; §11 and §12 record the version change and compliance mapping.

No measurements are recorded or re-scored by this correction. It is a normative
fix to a method that has not yet been executed by T142.

## 6. What the protocol records

`tools/evaluation/manual-baseline.md` is a normative method, not a result. It
contains no measured reduction, no expected value, and no placeholder presented
as data. Its sections define:

- **Normative sources and precedence** for SC-003, D-18, the frozen corpus and
  metric, and the constitution, including the per-form reading.
- **Terms and counting rules**: the four D-18 operation classes add, move,
  resize, and reclassify; net per-field/property counting; separate secondary
  counts for confirm, reject, remove, reorder, navigation, and committed
  operations; the undo/redo rule and the no-epsilon rule.
- **Equal conditions**: same operator, same tool/build, same authoritative
  Android device/profile, same PDF bytes, same ground truth and metric, same
  instructions, same zoom/pan policy, no values, offline, and same measurement
  schema.
- **Fair-comparison controls**: operator qualification and GT independence,
  preregistration and freezing, balanced condition order, at least 24-hour
  washout, a strict quality-parity gate (TP = GT count, FP = 0, FN = 0, every
  match same-type with IoU ≥ 0.5), required action-log instrumentation,
  condition blinding, and a no-tuning rule.
- **Execution and rerun rules**: precondition checks, per-form sequence,
  scoring sequence, and the rule that invalid or failed runs are retained and
  replaced only by a new separately reported run.
- **Metrics**: per-form `M_f`, `D_f`, `R_f`, untouched fields, and `U_f`;
  pooled `R_pooled`/`U_pooled` computed from totals **as context only**. SC-003
  requires both `R_f ≥ 0.80` and `U_f ≥ 0.80` for every form; one failing form
  fails the run. No form is excluded or substituted.
- **Required T142 record**: run identity, per-form table with a per-form SC-003
  verdict, per-form decision summary, pooled context values, and
  evidence/limitation fields.
- **Prohibited practices**: a benchmark-integrity table covering detection in
  the manual condition, GT access, per-form tuning, order changes, early
  stopping, form exclusion, rule changes, hidden work, selective reporting,
  pooled/averaged substitution, class mixing, and post-hoc re-scoring.
- **Reproducibility, limitations, versioning, compliance map, and a no-results
  statement.**

The protocol depends on artifacts that T033/T034/T142 have not yet produced
(`corpus-1.0.0`, `metric-definition.v1.md`, the scorer, and the T142 report).
They are named as frozen/later inputs, not as existing measurements. That is
why T035 is independent of T034 and why no SC-003 value can appear here.
