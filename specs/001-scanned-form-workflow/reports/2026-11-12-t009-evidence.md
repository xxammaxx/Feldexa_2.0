## 0. Review findings and response

The prior candidates failed review for four reasons:

1. **Plan says fixtures are dev-only, but pubspec declared them globally.**
   Flutter `flutter.assets` entries are packaged into every Android build,
   including release. Adding `- assets/fixtures/` therefore shipped development
   PDFs and OCR expectations in production Android.
2. **Browser runtime determinism was unverified.** Only host-side checks were
   recorded; no Chrome run exercised the fixture delivery path.
3. **The protected fixture was not password-gated.** `sf-protected.pdf` used an
   empty user password, so Poppler extracted its text without a password; only
   a wrong password failed. That does not represent the unsupported
   password-protected import case.
4. **The security-handler comment contradicted the fix.** `crypto.dart` still
   said the user password was empty and that readers open without prompting.

## 15. Limits

- The PDFs use base-14 Helvetica, not the bundled Noto Sans export path
  (T006/T007/T103 own that); these fixtures validate UI/geometry, not export
  font fidelity.
- Expected OCR is authored from the layout, not produced by ML Kit. It makes
  UI tests deterministic; it is not OCR-quality evidence.
- Browser evidence covers fixture delivery determinism only, not the editor
  journey, viewport behavior, or accessibility semantics.
- The release APK audit proves absence of fixture bytes; it does not claim
  release signing, installation, or runtime acceptance. It predates the
  password-only fixture change and is unaffected because fixtures are not in
  the APK.
- The protected fixture is a legacy 40-bit RC4 test artifact, not a
  cryptographic recommendation. Extractability with the documented user
  password is intentional; empty and wrong passwords fail.
- The canonical `assets/fixtures/` directory and the Web mirror deliberately
  duplicate generated bytes. The generator and integrity test keep them
  identical; a future consolidated delivery design can replace the mirror
  without changing the fixture contract.
- The plan's `assets/fixtures/` path is preserved as the canonical dev source;
  Web consumers must use `/fixtures/...` rather than `rootBundle`. T011/T028
  must implement that loader contract.
- This report is execution provenance and self-evidence, not an independent
  approval.
