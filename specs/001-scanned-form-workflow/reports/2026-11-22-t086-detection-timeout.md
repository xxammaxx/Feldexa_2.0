### 5.2 Fix, and what the index actually guarantees

`_detectBoxes` now asks `_VerticalRuleIndex` which vertical rules may be one
side of a box. The index encodes necessary conditions taken from the unchanged
corner test: a rule may be the `left` side only if its centre x lies within the
corner tolerance of both horizontal endpoints (`x0`) and its start and end y lie
within tolerance of the two horizontal centres; the `right` side is the same
with `x1`. Each query is two binary searches plus one window filter.

**The index is a necessary-condition superset, not an exact filter.** Every
side rule the corner test can accept is returned; rules that share the window
geometry but fail the corner test, the minimum-interior-size check, or the
duplicate-centre pairing rule are also returned and are then rejected by
acceptance logic, exactly as the exhaustive loop rejected them. The correct
claim is therefore that the index removes provably impossible combinations and
never removes a possible one, not that it "enumerates exactly the acceptable
combinations".

Both enumeration paths in `_detectBoxes` call the same `_considerBox` function,
which contains the pre-T086B predicates in their original order. The exhaustive
quadruple-nested loop is retained and reachable only through the test hook
`debugDetectExhaustiveBoxScan`, which production code never calls; `detect`
always takes the indexed branch. Keeping the shared acceptance function is what
makes the differential test in section 4 meaningful: the two paths differ only
in enumeration and pairing order, and the pairing rule (`right` index strictly
greater than `left` index) and ascending emission order are preserved.

No isolate, worker, timeout, or other architectural device was added. That work
is `T086B-R` (section 1).

  arbitrary pages.

  committed is a standalone script used by check 7, not a test-suite artifact.
- **No emulator or device evidence.** The T086A emulator worktree was not

  that the editor no longer times out is derived from the detector measurements,
  not observed on Android.
- **Browser entry check not applicable.** `apps/feldexa_app/test/web_recognition_browser_entry_test.dart`
