Implementation notes:

- The generator reads the two static TTFs directly. It requires `head`, `hhea`,
  `maxp`, `hmtx`, `cmap`, `glyf`, and `loca`; rejects `fvar`/`CFF `; verifies
  each source SHA-256 against the T006 pins; and fails if any FR-067 required
  German codepoint (ASCII, `ÄÖÜäöüß`, `€`, `„ “ ”`, en/em dash, ellipsis,
  no-break space) is missing or has a zero advance.
- The Unicode cmap is read through the best available format 12 subtable
  (format 4 is the BMP fallback). The table emits **all 3,094 mapped
  codepoints** per weight, in ascending numeric order, not only the required
  subset.
- A present `advances` key means the glyph exists and its value is the `hmtx`
  advance in design units. A missing key is a font-coverage failure for
  `EXP-004`, not a zero width. U+0301 is present with advance 0, which is a
  real combining mark.
- `metricsVersion` is `noto-sans-2.013-v1`, matching the value in
  `contracts/export-plan.md` §2, and `schemaVersion` is `1`.
- The output is deterministic: two runs are byte-identical, and `--check`
  regenerates in memory and compares the exact bytes.
- `apps/feldexa_app/pubspec.yaml` now packages `metrics.json` through
  `rootBundle`. The web build below proves the asset pipeline carries the
  exact bytes.
- `pubspec.lock` is byte-identical after dependency resolution. No dependency,
  Android source, font byte, or package changed.
