## 4. Behavior implemented vs specification

FR-001 is satisfied: `MainActivity` registers one
`ActivityResultLauncher<Array<String>>` over
`ActivityResultContracts.OpenDocument()` for MIME `application/pdf`, which
issues the ordinary `ACTION_OPEN_DOCUMENT` picker. Because `FlutterActivity`
extends the plain `android.app.Activity` (not `ComponentActivity`), the
launcher is hosted by a small concrete `ActivityResultRegistry` whose
`onLaunch` delegates to `startActivityForResult` and whose result is dispatched
from `onActivityResult`. No storage permission, custom browser, file path or
`File` conversion is used. The picked URI is consumed only through
`ContentResolver.openInputStream`, exposed by the narrow `PickedDocument`
seam. The `OpenableColumns.DISPLAY_NAME` query is resolved lazily, on the facade
worker thread that reads `displayName`, never on the main thread inside the
ActivityResult callback; the terminal value stays the same (name or null) and no
permission is added.

FR-095 is satisfied at the scope of this task: bytes read from the stream are
staged through the existing `EncryptedStore.stageSource` seam into app-private
encrypted storage. FR-009 is satisfied because a stage leaves the aggregate
incomplete (no `meta.fx1`/`head.fx1`), so a rejected or cancelled import is
never a visible document, draft, template or stored record.

`platform-channel.md` §2.4: the facade sends the start reply `{operationId}` and
publishes exactly one terminal result; `ImportService` returns only
method-specific data and never publishes a result. §3 terminal data produced by
T038: `sourceId`, `documentId`, `sha256`, `sizeBytes`, `displayName`.
`pageCount`/`pages` are deliberately absent — they are T039 PDF-preflight
outputs and inventing them would be out of scope. §3.2: the stream is counted
and SHA-256 hashed in bounded 64 KiB chunks with an 80 MiB (83,886,080-byte)
cap; exceeding it raises the existing `IMP-007` / `tooLarge` /
`import.tooLarge` mapping (no T045 wording, ARB key or catalog change).
`Context.checkCancelled()` is honored inside the read loop, after the loop,
during the picker wait, and in the post-staging cancellation decision. A
cancellation before staging creates no stage. A cancellation after staging runs
the registered staged-aggregate discard exactly once inside the operation
handle's cancellation linearization, before any cancellation result is
observable, including a cancel that arrives in the facade's post-handle window.
A failed discard is reported as the mapped non-cancelled storage failure, not as
a clean `PLT-004`. `import.verifySource` and `import.discardStaged` fail closed
with `PLT-001`/`platform.unsupported` — no wire shape is invented. Storage
exceptions are mapped with the same content-free codes/categories as
`StoreService`.

Deferred: T039 (PDF parsing, preflight, page geometry, encryption detection,
`pageCount`/`pages`), T040 (true streaming encrypted copy and import commit /
`EncryptedStore.kt`), T041 (Dart error mapper — no Dart touched), T045 (IMP-007
wording/ARB/catalog changes).

## 8. Limitations and open questions

* `EncryptedStore.stageSource` accepts a materialized `ByteArray`, so T038
  reads the stream in bounded chunks but necessarily materializes the source
  in memory (bounded to ≤ 80 MiB) before staging. A true streaming encrypted
  copy is T040 and is not implemented here.
* T038 stages an incomplete source aggregate; it does not perform PDF
  preflight, commit `meta.fx1`/`head.fx1`, or create a visible document. Those
  are T039/T040. Consequently `pageCount`/`pages` are absent from the terminal
  data.
* `import.verifySource` and `import.discardStaged` intentionally report
  unsupported until T039/T040 define their wire shapes.
* The staged-aggregate discard registered on the handle runs synchronously on
  the thread that invokes `cancel.operation` (normally the platform/main
  thread), inside the cancellation lock. It is bounded to one incomplete
  aggregate's local objects and performs no provider query or network I/O.
  This is the ordering cost of guaranteeing that no cancellation is observable
  while the aggregate is retained.
* If the discard fails, the terminal result is the mapped non-cancelled storage
  failure (`SAVE-*`), while the `cancel.operation` reply still reports
  `cancelled: true` because the cancellation itself won. The aggregate is then
  retained and remains invisible (no meta); the existing startup sweep is the
  fallback. The failure is recorded, never swallowed.
* The SAF picker itself was not instrumented: no emulator/device run, so the
  Activity-result path is verified only by construction and by the
  injectable-seam unit tests. The picker callback is exercised through a fake
  in HOST-JVM tests; the lazy display-name resolution is verified by code
  inspection and compilation, not by a provider-backed device test.
* No `IMP-007` wording, ARB key, error-catalog, Dart or Gradle change was made,
  per scope.
