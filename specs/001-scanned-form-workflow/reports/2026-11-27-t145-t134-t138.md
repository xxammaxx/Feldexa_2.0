   and the TCP header; failed reads are counted separately and fail the run;
   only successful reads count as samples. The app-UID loopback listener is a
   per-run positive control (port `9A61` observed), so `outbound=0` cannot be
   a vacuous unreadable-table pass.
2. **T134 thresholds:** large/normal is classified from the unscaled font size
   (`>= 18 px`, or `>= 14 px` bold); the 4.5:1 normal tier is now applied. A
   host regression proves 3.1:1 normal text is red (4/4).
3. **T134 semantics:** each control must own a labeled/tooltip semantics node
   bounded by its hit target and carry a tap action when enabled; the previous
   ancestor-node walk was always green and was removed.
4. **T134 counting:** controls are deduplicated by render-object identity, so
   M3 `IconButton` is counted once (editor 8, not 17).
5. **Manifest audit:** real XML element parsing plus a simulated main+release
   merge (139 checks) replaces substring coincidence.
6. **Wording/commands:** browser rows distinguish "not on the gate search
   path" from "binary absent"; the host lane command names
   `test/release_manifest_audit_test.dart`.

production `FeldexaApp` root on the emulator, arms the committed synthetic

## T138 — outbound/socket observation and release-manifest audit (SC-007/SC-008; FR-078/FR-079/FR-080; CHK020)

**Socket observation (`EMULATOR`).** Android 15 denies the app UID all
`/proc/net` access, so the integration test records that in-app tables are
unavailable and the host driver
`tools/android/t138_network_observe.sh` samples `/proc/net/tcp{,6}` from the
shell UID while the test runs, filtering every row to the app UID and to
ESTABLISHED/SYN_SENT/SYN_RECV/CLOSE_WAIT states with a non-loopback remote
address. The test itself additionally fails closed on any Dart
`HttpClient` creation and records the analysis terminal state.

Run: `tools/android/t138_network_observe.sh` →
`T138_OBSERVE:uid=10240:samples=89:read_failures=0:visible_rows=216:outbound=0:positive_control=1:port_hex=9A61:test_rc=0`,
`T138_OBSERVE_PASS`. Every read checks the adb/cat exit status and requires
the TCP header; failures are counted as `read_failures` and fail the run
instead of being counted as samples. The app opens an app-UID loopback
`ServerSocket` as a **positive control**; the driver had to see its exact
`0100007F:9A61` LISTEN row, so `outbound=0` is distinguishable from an
unreadable table. The journey reached `T138_ANALYSIS_TERMINAL:analysis-ready`
(import → encrypted staging → preflight → ML Kit OCR on both pages) and
`T138_NETWORK_AUDIT_COMPLETE` with `T138_SOCKETS:...:httpAttempts=0`. Scope:
startup, import, and first analysis; export is a local path covered by the
T108/T109 emulator runs and is not re-observed here. Sampling is one adb
round-trip at a time (~1 Hz on this host), so shorter TCP flows can be
missed.

**Release-manifest audit (`NONE`).**
`apps/feldexa_app/test/release_manifest_audit_test.dart` (shared
`test/support/release_manifest_audit.dart`, also invoked by the integration
test on the host leg) parses the four committed manifests and the app pubspec:
each permission and component is identified by its own XML element
(`android:name` + `tools:node="remove"`), not by two substrings anywhere in a
file; main+release are then merged element by element. The merged set contains
neither INTERNET/ACCESS_NETWORK_STATE nor any of the three ML Kit
DataTransport services/receivers, and the overlay has an explicit remove for
each of the five names; only debug/profile keep INTERNET for the Flutter tool;
no manifest is `debuggable` or permits cleartext; the debug import channel and
the synthetic fixture tree never appear as manifest/asset entries (assets are
parsed as YAML, including inline lists). The committed checker's negative
controls (`tools/android/check_release_manifest.sh --self-test`) pass on the
same tree. Result: `MANIFEST_AUDIT:PASS:checks=139`; host test **PASS**
(1/1). This is a static source audit, not a built-release artifact audit.

## Limitations

- T145 stays PARTIAL: both `SIMULATED` browser lanes remain
  `UNAVAILABLE`/`ABSENT` under the documented environment finding; no browser
  PASS is claimed. The gate exit code is 3 (INCOMPLETE), not a pass.
- T134/T138 ran on the debug Android build only; no `DEVICE`, release-build,
  print, or performance claim is made.
- The T138 kernel observation covers startup, import, and first analysis, not
  the complete import→export journey; it cannot see traffic from other UIDs and
  makes no claim about them.
- The release-manifest audit parses and merges the committed source manifests;
  it does not inspect an AGP-merged release manifest or APK (none was built in
  this slice).
- T138 samples the kernel table one adb read at a time (~1 Hz), so TCP flows
  shorter than one read can be missed; the result is a lower bound, not a
  per-packet capture. Other UIDs are outside the claim.
