## 3. Behavior delivered

### 3.1 Deterministic default order and stable identity

- `compareFieldsInDocumentOrder` implements the `data-model.md` §7 tie-breaker
  chain exactly: page index → stored `rect.top` → stored `rect.left` → field id.
  It never rounds or quantizes geometry, and the id is the final total
  tie-breaker.
- `defaultDocumentFieldOrder(content)` is the canonical
  `ReviewOrderMode.pageOrder` projection. It is independent of the caller's
  list order and is also the defensive completion order for a degenerate
  snapshot.
- `orderedFields(content)` / `fieldOrderIds(content)` return the current
  user-visible order from `RevisionContent.fieldOrder`
  (`ReviewOrderMode.documentOrder`, `data-model.md` §3.12). Confirmed fields are
  appended in analysis order, so a freshly reviewed document already starts in
  page and reading order; T073 never rewrites the stored order silently.
- `resolveFieldOrder(fields:, fieldOrder:)` fails open: unknown or repeated ids
  are skipped and unmentioned fields are appended in deterministic order, so a
  degenerate id list cannot drop a field or throw. Empty input yields an empty
  list.

### 3.2 Review list metadata (contract §3)

`FieldOrderEntry` exposes exactly the required fields: `fieldId`, zero-based
`position`/one-based `number` (index), `pageIndex`, stored `label`, `type`,
`provenance`, `confidence` (machine fields only; null otherwise), `conflicting`
(true while the source suggestion still carries symmetric conflict references),
and `completion` from the T085 `fieldCompletionState` classifier. The widget
renders all of them plus German type/provenance/completion labels.

### 3.3 Reordering (FR-026)

- `moveFieldToIndex`, `moveFieldUp`, `moveFieldDown` return a complete,
  revalidated `core.RevisionContent`. Only `fieldOrder` and the affected fields'
  `order` values change; pages, suggestions, values, signatures, verification,
  template origin, and unknown extensions are carried through verbatim, so a
  reorder cannot lose a value or geometry. Layout validation runs again in the
  `RevisionContent` constructor.
- A no-op request returns the input snapshot with `changed == false`; the editor
  does not persist it.
- Unknown ids throw `FieldOrderException(fieldNotFound)`; out-of-range targets
  throw `indexOutOfBounds`. The message and `toString` are content-free.
- Boundary moves return null, so the move-up/move-down controls are disabled at
  the ends rather than hidden.
- The operation is clock-free and writes no timestamp; the durable record is the
  autosave revision.

### 3.4 Undo (contract §8, FR-027 wiring)

`EditorScreen` commits each move through the existing verified `_commitSnapshot`
path with `history.EditCommandKind.reorder` and the moved `fieldId`. Reorder is
a field-scoped, non-coalescing kind, so every move is exactly one T067 undo
step; undo applies the exact previous snapshot (order, values, geometry). A
failed save records no history entry and leaves the stored order untouched.

### 3.5 Selection, next/previous, values (US3-8, US4-4, contract §2/§5)

`nextFieldId` / `previousFieldId` walk the current order, start at the first /
last field when nothing or an unknown field is selected, and return null at the
boundary without wrapping. The editor sheet wires them to
`Vorheriges Feld`/`Nächstes Feld`: the target field is selected and its page is
scrolled into view. Both are view-state only — no value, geometry, or order is
written — so previously entered values remain intact. A row tap selects that
field and closes the sheet; it never opens a value control or invents a value.

### 3.6 German text

13 new ARB keys were required because no existing key expresses the field-order
title, move actions, traversal, position index, empty state, or the five T085
completion labels. They were added to `app_de.arb` with descriptions, generated
with `flutter gen-l10n`, and added to the `_nonCodeArbKeys` allowlist in
`german_strings_test.dart`. Provenance reuses the existing allowlisted
`a11yFieldStatusConfirmed`, `a11yFieldStatusSelfCreated`, and `templateLabel`;
conflict reuses `suggestionConflict`, page reuses `suggestionPage`, type reuses
`suggestionType*`, and confidence reuses `suggestionConfidence`.

  task: `DocumentPreferences` is not part of `RevisionContent`, so the default
  review order remains the stored document order (`documentOrder`). The
  page-order projection is exposed as `defaultDocumentFieldOrder` for a later
  preference-wiring task; no preference UI or storage was added.

  clock-free; the autosave revision is the durable record of the change.
- The review list is a modal sheet opened from the app bar, not an inline
  section of the existing suggestion panel, because the space above the page
  viewport is already bounded by the IME-safe warning and suggestion headers.
