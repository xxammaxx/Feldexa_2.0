## 3. Behavior delivered in this correction

### 3.1 Per-field entry point (contract §3)

- `FieldValueSheet` always renders „In Reihenfolge verschieben“ (`OutlinedButton`,
  key `field-value-reorder`) for every field type. It commits the current draft
  first (same `_commitDraft` path as save/Enter/focus loss), then pops with
  `FieldValueSheetOutcome.reorder`. A failed commit keeps the sheet open with the
  existing error, so no draft is lost and no order review is opened on a failed
  save.
- `EditorScreen._openFieldValueSheet` awaits that outcome and opens the FR-026
  order review. The value sheet and the app-bar action are the two documented
  entry points; the order review also exposes the page-order action.

### 3.2 Focus traversal (contract §5, US4-4)

- `FieldValueSheet` gained `onNavigate`, `canGoPrevious`, and `canGoNext`.
  Previous/next buttons (keys `field-value-previous`/`field-value-next`) are
  disabled at the order boundaries and while a commit is in flight.
- `_navigate` commits the draft, then hands the direction to the editor. The
  editor resolves the target with `nextFieldId`/`previousFieldId` from the
  latest `_content`, selects it (`scrollToPage` + selection), and rebuilds the
  still-open sheet with a new per-field key so the new control takes focus.
  Values commit before the swap; no write happens for a boundary or a failed
  commit.
- Signature fields have no storable value, so navigation skips the commit but
  still swaps the field.

### 3.3 Page order, live snapshot, conflict, preservation

- `isInPageOrder` / `moveFieldsToPageOrder` add the `ReviewOrderMode.pageOrder`
  projection as a one-step reorder (FR-026 names page and document order).
- Order moves and the page-order action read `_content` at operation time; a
  no-op refresh prevents a stale rendered list.
- `hasOpenSuggestionConflict` makes the field-order conflict badge clear once the
  opposing candidate is resolved (stale references stay visible).
- The shared fixture’s non-null template origin and field extension are asserted
  across reorder and JSON round-trip.

## 6. NOT_RUN and explicit omissions

- **§2 long-press „Feldreihenfolge“ context menu is not implemented.** The
  overlay gesture layer is T071B-owned: one-finger body drags are geometry
  edits, and the integrated T071 Android touch test deliberately holds those
  drags for 1160–1991 ms. Adding a long-press recognizer to the page overlay
  would fire during those holds and change integrated T071 behavior, so it
  cannot be done safely inside this correction. The omission is explicit; the
  §3 per-field action provides the field-order entry point. Closing this needs a
  separate gesture-arbitration task and a T071 Android rerun.
- No emulator, device, browser, screenshot, logcat, APK, or Gradle evidence; no
  runtime evidence class is claimed.
- Drag-to-reorder is not implemented; FR-026/contract §3 allow “drag or move
  up/down” and the explicit actions are tested.
- A UI-level “content changes while the order sheet is open” test is not
  practical without a test-only content mutation hook; the live-read code path
  and the model-level stale/live test are recorded instead.
- TalkBack/screen-reader walkthrough, visual contrast audit, and a German copy
  review beyond `german_strings_test.dart` are `NOT_RUN`.
- `ReviewOrderMode.pageOrder` is not persisted as a document preference
  (`DocumentPreferences` is not part of `RevisionContent`); the page-order
  action makes the page order reachable and undoable without a preference UI.
- Reordering does not bump `ConfirmedField.updatedAt`, keeping the operation
  clock-free; the autosave revision is the durable record.
