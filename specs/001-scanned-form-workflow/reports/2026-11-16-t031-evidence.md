## 9. Limitations and residual risks

- **In-flight native step.** The deadline is cooperative between actions. A
  single destructive operation already started — one `deleteTree`, one
  signature delete, one prune call that has begun, or one alias delete — may
  complete before the next check. No new destructive action starts after the
  deadline, and the event and report reflect that the run was stopped.
- **Clock source.** The deadline is wall-clock epoch milliseconds, computed in
  Dart and compared with the native `clock()`. A system clock jump between the
  two reads can make the bound early or late; normal startup does not change the
  clock.
- **Reads before a check.** The template-reference scan and signature-reference
  collection are reads; they may run until the next deadline check, but they
  delete nothing.
- **Step-4 exception.** The plaintext export-preview cleanup still runs first and
  is not interrupted by the deadline (owner decision 2026-11-17); it is bounded
  and reports failures. This report does not claim otherwise.
- **Emulator scope.** Only `SignatureSweepInstrumentedTest` (3 tests) ran by
  class filter; the other instrumentation classes were compiled but not run in
  this round. The Dart integration test exercises the production sweep class
  and the real cache directory, not a full process restart.
- **No independent review.** This is an author report, not an approval; the
  review table in §11 is blank.
- **Device release form.** The bare `orca-ide emulator kill --json` returned
  `emulator_no_active`; the explicit device/worktree kill succeeded (see §5.3).
