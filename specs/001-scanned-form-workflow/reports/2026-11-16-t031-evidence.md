## 5. Correction findings and exact changes

### T031-B1 — production adapter and real startup wiring

- `apps/feldexa_app/lib/bootstrap/startup_sweep_io.dart:31` defines
  `IoStartupSweepFileSystem`. It enumerates only
  `<Directory.systemTemp>/feldexa_exports`, lists one level without following
  links (`:75`), deletes only a single safe file name inside that directory
  (`:126`), and refuses directories and links with canonical `PLT-002`.
- The adapter explicitly reports **no** staging entries (`:55`) and refuses a
  staging delete (`:65`): `filesDir/feldexa/tmp` is owned by native T026. It
  does not re-implement, duplicate, or guess native recovery.
- `apps/feldexa_app/lib/bootstrap/startup_sweep_app.dart:23` selects the
  platform composition with the same conditional-import pattern as
  `apps/feldexa_app/lib/platform/registry.dart`.
- `apps/feldexa_app/lib/bootstrap/startup_sweep_app_android.dart:28` composes
  the real T027 `AndroidPlatformRuntime`, its `AndroidStoreClient`, its native
  `runStartupRecovery`, and the io export adapter. The runtime's raster/OCR
  resolvers are startup-only fail-closed placeholders because startup owns
  neither loaded-document bytes nor page geometry; startup never calls them.
- `apps/feldexa_app/lib/bootstrap/startup_sweep_app_web.dart:20` composes the
  Web branch with no store and a fail-closed no-op directory, and imports no
  `dart:io` or adapter package.
- `apps/feldexa_app/lib/main.dart:7` now runs the sweep before `runApp`;
  `:11` constructs the production sweep; `:14` invokes the bounded runner;
  `:81` renders localized recovery notices. Construction/runner failures are
  caught and become a degraded startup state, never a crash.
- `apps/feldexa_app/lib/bootstrap/startup_sweep_bootstrap.dart:69` bounds the
  wait, converts a timeout or a thrown run to a degraded value, and consumes a
  late error from a timed-out operation so it cannot become unhandled.
- Host tests: `apps/feldexa_app/test/startup_wiring_test.dart:47` proves the
  platform selector builds the real store/io adapter; `:59` proves the bounded
  timeout, thrown-run, clean, and degraded outcomes;
  `apps/feldexa_app/test/startup_sweep_test.dart:657` covers the production io
  adapter (listing, native-staging refusal, directory refusal, full sweep age
  behavior, missing directory).
- The Web build in check 8 passes, which is the executable evidence that the
  Web branch does not resolve `dart:io`, the Android runtime, or the adapter
  package.

### T031-A1 — native fallback adoption preserved across later reads

- `apps/feldexa_app/lib/bootstrap/startup_sweep.dart:894` preserves a positive
  native `fallbackAdoptions` count as a store-wide `SAVE-004` notice when no

  `nativeFallbackCount` separately from the later stamp-only `fallbackCount`.
- Regression test:
  `apps/feldexa_app/test/startup_sweep_test.dart:265`,

  `SAVE-004` notice with the ARB status label, message, and recovery text.
  This is the transition the first-round fixed-stamp test did not exercise.

### T031-A2 — native failure must not skip plaintext cleanup

- Corrected test:

### T031-B2 — export step 4 before native steps 5–6

## 8. Limitations

- This is `NONE` host evidence. It cannot prove Android Keystore,
  MethodChannel, encrypted-store, native T026, real cache-directory, emulator,
  device, browser, or performance behavior.
- The Dart io adapter assumes the Android `Directory.systemTemp` is the app
  `cacheDir`, as stated by the correction brief and the T031 task. That
  assumption is not runtime-verified here.
- The Dart layer cannot safely address `filesDir/feldexa/tmp`; native T026 owns
  it. The adapter returns no staging entries and refuses a staging delete
  rather than pretending to sweep it.
- `startup_sweep_app_android.dart` composes the full T027 runtime with
  fail-closed raster/OCR resolvers because the startup path does not own those
  capabilities. Only the store and native recovery are used. The real editor
  composition remains a later bootstrap obligation.
- A generic startup timeout/throw has no catalog key that describes this
  condition. No new ARB key was invented and no German text was hard-coded.
  The app therefore shows no completion or success indicator for that case; it
  starts in the normal shell and the internal state is degraded. No false
  success is reported.
- The literal root-cwd `flutter test apps/feldexa_app` still fails for the
  pre-existing integration-test/cwd reasons; the package-directory invocation
  passes 107 tests.
- The `reports/README.md` §9 index row for this report was not added because
  that file is outside T031's allowed write scope. This remains an open
  integrator index finding.
- The T032 evidence-doc checker and report validator were not run; they verify
  a report against a committed revision and the README index, and the index row
  is outside this task's allowed write scope. They remain a reviewer/integrator
  step.
- Session-end invocation of `sweepSessionEnd()` remains a later preview
  lifecycle obligation (T106); this shell wires the startup sweep only. The
  Android force-stop recovery test (T092) and plaintext-residue instrumentation
  (T098) remain their own runtime gates.
- No independent review has occurred. The reviewer section is blank; this
  author report is not approval.
