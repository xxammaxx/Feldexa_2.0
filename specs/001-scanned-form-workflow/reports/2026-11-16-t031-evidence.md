## 1. Scope

This report covers the T031 application-side startup sweep in
`apps/feldexa_app/lib/bootstrap/` and its host-VM failure-case tests. It
implements the ordered behavior required by:

- `contracts/storage-format.md` §4 steps 1–6 — startup recovery order;
- `contracts/storage-format.md` §3.1 step 8 — the bounded known-kind retention
  rule and the delete-directory-fsync gate remain native T026 obligations;
- `contracts/storage-format.md` §3.4, §3.5, §3.6 — signature assets, export
  artifacts, and aggregate deletion;
- `contracts/storage-format.md` §5 — `SAVE-001`/`SAVE-002`/`SAVE-003`/
  `SAVE-004`/`SAVE-008` durable-state and user-facing semantics;
- `contracts/ports.md` §2.4 — `StoreKind`, `StoredMeta`, `RecoveryStamp`, and
  the `list`/`recoveryStamp` reads;
- `plan.md` §Constraints — no plaintext in caches, temp files, or backups, and
  export previews live only in app-private cache until preview dismissal or
  startup/session-end sweep;
- constitution Principles VI, VII, and VIII.

The division of labour is the one stated in
`apps/feldexa_app/lib/bootstrap/android_platform_runtime.dart`: native T026
owns stale `tmp/`, incomplete aggregates, head fallback, signature assets, and
orphan KEK aliases. T031 binds that recovery through a conditional platform
seam, invokes it before any Dart read, and then performs only the
contract-visible `list`/`recoveryStamp` reads plus the cache-directory
export-preview sweep that the native store does not own. On the Web the native
seam is `null`; no Android runtime or adapter package is resolved.

## 7. Limitations

- This is `NONE` host evidence. It cannot prove Android Keystore, MethodChannel,
  encrypted-store, real cache-directory, emulator, device, browser, or
  performance behavior.
- The native T026 recovery was not executed. Android binding is proven only by
  static composition and the `null`/non-Android selector test; the
  `AndroidRecoveryReport` conversion is host-compiled, not runtime-tested.
- The concrete `dart:io`/channel-backed `StartupSweepFileSystem` for the
  `filesDir/feldexa/tmp` and `cacheDir/feldexa_exports` directories is a
  composition-root responsibility and is not part of T031's allowed write
  scope. T031 provides and tests the bounded seam; the native T026 store owns
  the real `tmp/` sweep on Android.
- The filesystem seam assumes the implementation enumerates only the two
  dedicated app-private directories and deletes only returned entries. That
  assumption is documented on the interface and is not independently proven by
  a host fake.
- The literal root-cwd `flutter test apps/feldexa_app` invocation fails for the
  pre-existing cwd/integration-test reasons in §4.3; the supported
  package-directory invocation passes.
- No candidate SHA or own report hash appears here by design (`reports/README.md`
  §4.1); both are in the external dispatch completion record.
- The `reports/README.md` §9 index row for this report was not added because
  `specs/001-scanned-form-workflow/reports/README.md` is outside T031's allowed
  write scope. This is an open index finding for the integrator.
- The `tools/evaluation/check_evidence_docs.py` and
  `tools/evaluation/validate_report.dart` pre-review checks were not run: they
  verify a report against a committed revision and the `reports/README.md`
  index, and the index row is outside this task's allowed write scope. They
  remain a reviewer/integrator step.
