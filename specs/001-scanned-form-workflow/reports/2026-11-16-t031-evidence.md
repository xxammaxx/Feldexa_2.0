## 6. Correction round 2 — findings and exact changes

### 6.1 T031 A-1 — §4 step 3 now runs in production

The contract decides ownership:

- `contracts/platform-channel.md` §4 (line 230): `store.startupRecovery` is
  synchronous and exposes the T026 native recovery, including unreferenced
  signatures; T031 must call it and must not duplicate the native sweep.
- `contracts/storage-format.md` §4 step 3: delete unreferenced signature
  assets older than 24 h; an asset is removed only if no revision or template
  version references it and it is older than 24 h.

Implemented in `EncryptedStore.kt`:

- `:88` keeps the injected `signatureReferenceResolver` as an explicit test
  override.
- `:1139` runs step 3 unconditionally: an injected resolver is used when
  present; otherwise `sweepUnreferencedSignaturesFromCommittedContent()` is
  the production default.
- `:1238` is the default sweep. It early-outs when no document has a signature
  asset, scans template versions, and then each document.
- `:1277` scans each document's decrypted revision plaintext for its own
  on-disk `.fxs` asset ids. The canonical revision text carries the id in the
  signature mark; no JSON parser and no new dependency is introduced.
- `:1327`/`:1342` scan decrypted template-version plaintext for UUIDv4 tokens,
  covering a template-version-only reference.
- `:1373` deletes only direct `sig/<uuid>.fxs` files that are old, not in the
  reference set, and have a usable positive timestamp. A directory, symlink,
  non-`.fxs`, unknown id, unreadable timestamp, or any scan uncertainty keeps
  the asset. No file outside `sig/` is touched.
- `:1231` documents the conservative rule: any unreadable/corrupt revision or
  template version makes the whole scan uncertain and deletes nothing.
- `MainActivity.kt:56` constructs the store **without** a resolver; the comment
  at `:27` records that production therefore uses the default resolver. The
  `store.startupRecovery` channel payload is unchanged; no new wire field is
  added.

JVM regressions in `EncryptedStoreTest.kt`: `:736` unreferenced old deleted +
referenced kept; `:756` template-version-only reference kept; `:780` fresh
unreferenced kept; `:792` corrupt revision keeps the asset. The production
store in `setUp` has no injected resolver.

Instrumentation coverage: `SignatureSweepInstrumentedTest.kt:28` class, `:53`
production sweep, `:119` corrupt-revision keep. Status `NOT_RUN` (§4.3).

### 6.2 T031 A-2 — symlinked export root and real-path containment

`startup_sweep_io.dart` now:

- refuses a symlinked root before enumeration (`:90`) and again before every
  deletion (`:184`);
- resolves the real root with `resolveSymbolicLinks` (`:195`);
- resolves each candidate's real path (`:219`) and refuses a real path that is
  not exactly `<resolved-root>/<single-segment-name>` (`:224`);
- treats a symlink entry as a redacted inspection failure during listing
  (`:119`), so it is never returned for deletion;
- keeps the direct deletion guard for a directory/link/non-regular entry.

Regressions in `startup_sweep_test.dart`: `:766` symlinked root deletes
nothing outside and reports `PLT-002`/degraded; `:806` symlinked entry outside
target is kept and the sweep degrades; `:847` direct adapter deletion of a
symlink is refused; `:881` a regular old file in the real root is still
deleted.

### 6.3 T031 A-3 — rejected/uninspectable entries are redacted failures

- `startup_sweep.dart:149` defines `StartupSweepInspectionReporter`; `:676`
  and `:691` fold its count into `StartupSweepRemoval.failed`/`scanned`, add a
  cleanup issue, and therefore force `degraded`.
- `startup_sweep_io.dart:45`/`:81` reset and accumulate the count; `:119`
  (symlink), `:128`/`:151` (rejected names), `:137` (uninspectable stat), and
  `:156` (list failure) count without exposing any name or path. `:163` returns
  and resets the count.
- Regressions in `startup_sweep_test.dart`: `:906` a backslash name is a
  redacted failure and the file is untouched; `:941` a broken/uninspectable
  entry is a redacted failure and remains. Both assert that neither the issue
  text nor the removal text contains the offending name.

### 6.4 T031 A-4 — accurate order and timeout claims

- `startup_sweep.dart:23` and `:493` now state the EXACT effective order
  **4 → 1 → 2 → 3 → 5 → 6**, not the strict §4 order 1 → 2 → 3 → 4 → 5 → 6.
  The code no longer claims “required order” or exact fulfilment. Closing the
  deviation would require splitting the monolithic native recovery into two
  calls so step 4 can sit between native step 3 and native step 5; that is a
  contract change and a later, separately decided item.
- `startup_sweep_bootstrap.dart:65` now says the timeout bounds the **caller's
  wait**, not the recovery execution. A timed-out sweep may still perform
  native head repair, revision pruning, alias removal, and later store reads;
  its eventual error is consumed, and the UI receives a degraded startup state.

## 9. Limitations

- This is `NONE` host evidence. It cannot prove Android Keystore,
  MethodChannel, encrypted-store, native T026, real cache-directory, emulator,
  device, browser, or performance behavior.
- The native default resolver reads each candidate revision/template-version
  plaintext sequentially to scan for asset ids. Revision plaintext is bounded
  by the existing 32 MiB revision cap and is released per object, but recovery
  now materializes that plaintext instead of only hash-verifying chunks.
- The template reference scan is global for the store: if any template version
  is unreadable, no signature asset is deleted anywhere in that run. This is
  deliberately conservative.
- The Dart io adapter assumes Android `Directory.systemTemp` is the app
  `cacheDir`; `filesDir/feldexa/tmp` remains native T026-owned and is not
  addressed by Dart.
- Android instrumentation is `NOT_RUN`; no emulator/device allocation was
  available. The new class is named in §4.3 for a maintainer run.
- The literal root-cwd `flutter test apps/feldexa_app` still fails for the
  pre-existing integration-test/cwd reasons; the package-directory invocation
  passes 113 tests.
- The host JVM suite needed the workspace-local JDK/jlink shadow described in
  §3. That is an environment workaround, not a product change.
- The `reports/README.md` §9 index row and the T032 evidence checker/validator
  remain outside T031's allowed write scope; they are an integrator/reviewer
  step.
- No independent review has occurred. The reviewer section is blank; this
  author report is not approval.
