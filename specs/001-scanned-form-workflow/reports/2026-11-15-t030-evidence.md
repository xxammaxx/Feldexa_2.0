## 6. Contract analysis

The test deliberately does not import the T007 generator. It reads the bundled
TTFs and `metrics.json` directly and re-derives the contract with a second Dart
implementation of the sfnt tables the schema uses:

- `head` (`unitsPerEm`), `hhea` (ascender/descender/line gap, `advanceWidthMax`,
  `numberOfHMetrics`), `maxp` (`numGlyphs`), `hmtx` (per-glyph advances),
  `cmap` format 12 (Unicode coverage), and `OS/2` (weight class, typographic and
  Windows metrics, x-height, cap height).
- The comparison is exact, not tolerant: all **3,094** mapped codepoints per
  weight must have the same key set and the same integer advance in the JSON
  and the TTF-derived table.
- The format 12 subtable length is authoritative: before the first group read,
  `numGroups` must satisfy `groups <= (length - 16) ~/ 12`. The division avoids
  a `groups * 12` overflow and keeps every group inside the declared subtable
  rather than in whatever table follows it.
- A present key means the glyph exists; its value is the `hmtx` advance in
  design units. A missing key is an `EXP-004` coverage failure, not a zero
  width. U+0301 is present with advance 0 as a real combining mark.
- Width in points is `sum(advance[cp] for cp in text.runes) * fontSizePt /
  unitsPerEm`; schema v1 intentionally has no kerning or ligatures, matching
  the plain advance sum PDFBox uses.
- The single-line clip rule is `measuredWidth > rect.width − 3.0` (1.5 pt
  padding on both sides), from `contracts/export-plan.md` §3.1.

## 6a. Review correction: cmap group-array bounds

**Root cause.** `_readCmapFormat12` validated the declared subtable length and
the cmap-table end, but not whether the `numGroups` entries fit inside the
declared length. A subtable with a short declared length and a larger group
count could therefore read group fields from the following table's bytes.
`_u32` only fails at the whole-font end, so this was a real bounds escape, not
merely an early-error preference.

**Reproduction.** A synthetic sfnt fixture declares a 28-byte format 12
subtable (16-byte header plus one 12-byte group) and `numGroups = 2`. The bytes
for the second group are the `zzzz` table immediately after `cmap`, shaped as a
valid group for U+0042. Before the fix the parser returned
`{0x41: 1, 0x42: 2}`; the negative test failed with `[E] ... Actual: returned
{65: 1, 66: 2}`.

**Minimal fix.** The parser now checks
`groups > (length - 16) ~/ 12` before the first group read and throws
`StateError('cmap format 12 group array is truncated')`. Division avoids a
`groups * 12` overflow and guarantees each group read stays inside the declared
subtable. A positive control with `numGroups = 1` still parses to `{0x41: 1}`;
a second negative case with `numGroups = 0xFFFFFFFF` is rejected immediately.
The three synthetic tests live in the `malformed sfnt bounds` group.
