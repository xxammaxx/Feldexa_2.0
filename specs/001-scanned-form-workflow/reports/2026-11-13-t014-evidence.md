### 5.1 Strict runtime token rules

`CapabilityEvidence` is now intentionally **non-const**. A `const` constructor
cannot run validation in a release build, where assertions are disabled, so the
contract's illustrative `const CapabilityEvidence(...)` is superseded by the
security requirement. T013 and T028 must construct it at runtime.

- `adapterId`: 1–64 characters, `^[a-z][a-z0-9_-]*(\.[a-z0-9_-]+)+$`, at
  least one dot-separated segment, no document/image extension segment.
- `simulatedReason`: 1–96 characters, the same lowercase segmented grammar,
  only for simulated evidence, no document/image extension segment.
- `fieldIds`: 1–128 characters, `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`, unique.
- `EvidenceClass.parse` rejects unknown tokens with a constant message.
- Every rejected value is omitted from both the `ArgumentError`/`FormatException`
  message and `toString()`.

The extension denylist (`pdf`, `png`, `jpg`, `jpeg`, `gif`, `webp`, `heic`,
`txt`, `json`, `xml`, `csv`, `doc`, `docx`, `eml`, `zip`, `fx1`) closes the
obvious path/file-name channel while still allowing legitimate identifiers such
as `android.pdfbox.v1` or `web.sim.export.v1`.

### 6.2 `EvidenceClass` and `CapabilityEvidence`

- Exactly four classes in the contract order: `simulated`, `emulator`, `device`,
  `none`; report tokens are `SIMULATED`, `EMULATOR`, `DEVICE`, `NONE`.
- `parse` accepts an enum name or report token case-insensitively and throws a
  constant `FormatException` for anything else; `tryParse` returns `null` only
  for an unknown token. There is no silent `NONE` fallback.
- `isAndroid` is true only for emulator/device; `isRuntime` is false only for
  `NONE`.
- `CapabilityEvidence.simulated` is derived from `evidenceClass`, so the
  contract's "true iff simulated" invariant cannot be violated by a caller.
- `CapabilityEvidence.simulated` covers the `plan.md` §Architecture Decisions 9
  idiom; `CapabilityEvidence.android` declares `none` for a real Android
  adapter. The environment class is attached by the harness, never by the
  adapter.
- Adapter ids and reasons are validated at runtime, not only by assertions, and
  are omitted from log-style `toString()` output.

### 6.3 Error taxonomy

Every exception extends `FeldexaException` and carries `code`, `messageKey`,
`message`, `retryable`, and `severity`. Severity is an internal triage value
(`INFO`, `WARNING`, `ERROR`, `FATAL`), never a user string. The table below
matches `contracts/ports.md` §3 exactly.

| Exception | Code | Retryable | Severity |
| --- | --- | --- | --- |
| `ImportRejectedException(kind)` | `IMP-*` | no | `ERROR` (warning for `tooLarge`) |
| `ImportCancelledException` | `IMP-000` | yes | `INFO` |
| `StorageFullException` | `SAVE-001` | yes | `ERROR` |
| `KeyUnavailableException` | `SAVE-002` | no | `FATAL` |
| `CorruptDataException` | `SAVE-003` | no | `FATAL` |
| `StorageWriteException` | `SAVE-003` | yes | `ERROR` |
| `SecurityException` | `PLT-002` | no | `ERROR` |
| `SchemaTooNewException` | `SAVE-005` | no | `ERROR` |
| `ExportBlockedException(fieldIds)` | `EXP-001` | yes | `WARNING` |
| `ExportFailedException` | `EXP-002` | yes | `ERROR` |
| `RenderException(pageIndex)` | `PAGE-001` | yes | `WARNING` |
| `OcrUnavailableException` | `REC-001` | yes | `WARNING` |
| `SimulatedInProductionException` | `SIM-001` | no | `FATAL` |
| `UnsupportedOperationException` | `PLT-001` | no | `ERROR` |

`SAVE-003` keeps two distinct concrete causes: `CorruptDataException` (read-side,
non-retryable, ciphertext untouched) and `StorageWriteException` (write-side,
retryable, previous head intact). They share the catalog code but not the class
or machine message (`contracts/storage-format.md` §5).

`ImportRejectionKind` maps to the catalog as follows: `passwordProtected` and
`unsupportedEncryption` → `IMP-001`; `missing` → `IMP-003`; `unreadable` and
`truncated` → `IMP-002`; `notPdf` and `unsupportedStructure` → `IMP-004`;
`tooLarge` → `IMP-007`; `unknownReason` → `IMP-005`. `storageFull` and
`cancelled` map to `SAVE-001`/`IMP-000` only for routing, because
`contracts/ports.md` §2.1 requires `StorageFullException` and
`ImportCancelledException` for those causes; `ImportRejectedException` rejects
them instead of inventing an `IMP-*` code.

`ExportBlockedException` stores a defensive, unmodifiable, unique list of
identifier-only field ids; paths, file names, whitespace, and free-form content
are rejected. `RenderException` stores a non-negative zero-based page index.
`toString()` contains only the runtime type, code, machine message, retry flag,
and severity; messages reject German sentences, spaces, slashes, and path
shapes, and validation errors never echo rejected input.
