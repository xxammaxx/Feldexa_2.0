## 4. Metric definition (declared before scoring)

No composite headline. Three families are reported apart, exactly as research
D-18 and issue #263 require.

**(a) Raw OCR character fidelity — `EMULATOR`-agnostic, no normalization.**
Ground-truth and OCR text are compared as Unicode code points. Lines are
associated by geometry only: the OCR line's vertical centre inside the
ground-truth line box grown by 4 pt, and ≥ 30 % horizontal overlap of the
narrower box; pairs are assigned greedily by vertical distance. CER = Levenshtein
distance over the alignment divided by the ground-truth code-point count;
unassociated ground-truth characters are deletions and unassociated OCR
characters are insertions, so nothing leaves the denominator. Special-character
precision/recall and the confusion matrix come from the same alignment over the
11 required characters only.

**(b) Unicode representation checks.** Exact NFC equality per line, NFD-form
output, combining marks in the OCR output (`U+0300…U+036F`), missing umlaut
dots (`ö`→`o` at an aligned position), `ß`→`B` (`StraBe`-class confusion), and
lines whose OCR text equals the ASCII fold of the truth (`ss` for `ß`, `ae` for
`ä`). These are reported separately from CER, because a normalization or
representation defect is not a character-recognition percentage.

**(c) Semantic label/type assignment.** Recorded production suggestions
(`AnalyzeDocument` output) are matched to ground-truth fields with the
metric-definition.v1 rule (IoU ≥ 0.5, one-to-one, extras = FP, unmatched = FN).
Type accuracy and label accuracy are reported **among matches**; matching for
labels uses only the declared aliases. The scorer additionally counts
integrity violations: a suggestion with no label but a `keyword_*` cue (forced
type), a label that is not verbatim OCR text (silent normalization), and a
suggestion that is pre-resolved without a user decision.

An `UNRESOLVED` variant (critical line or reference label not exact, thresholds
met) is reported as `UNRESOLVED` and is never an accuracy PASS. The overall
verdict is PASS only when the reference variant is `EMULATOR` and `PASS`, and
under `--require-device-evidence` every executed variant ran on the emulator
(`EMULATOR` or `EMULATOR_INJECTED_RASTER`); `SIMULATED` and `TEXT_LAYER` runs
never satisfy that gate, and the report keeps `deviceEvidence` true only for the
clean `EMULATOR` class.

**Degraded-variant construction.** The production pipeline maps raster pixels to
page points with the fixed `200 / 72` analysis scale, so every injected raster is
normalised to the 200 DPI grid (1654 × 2339 px for A4); a 150 DPI capture is
upsampled, which keeps the geometry mapping valid while the resolution loss stays
in the content. For the clean 150/300 dpi variants only the raw OCR capture uses
that DPI — `AnalyzeDocument` always analyses its own 200 DPI raster, so those
variants qualify the DPI effect on raw text and say so in their description.

## 6. Proven defect and RED/GREEN regression (label normalization)

**Defect.** `TypeInference._normalizeForMatching` folded precomposed
`ä→ae, ö→oe, ü→ue, ß→ss`, but not NFD spellings (`a` + U+0308 …). An OCR engine
that emits decomposed umlauts therefore lost the lexeme match for
`Geschäftszeichen`, silently degrading the label cue set.

**RED (recorded before the fix).** Five tests were added to
`packages/feldexa_recognition/test/type_inference_test.dart` and run against the
unmodified implementation: 2 failed, 50 passed —
`NFD-decomposed umlauts match their composed lexicon spelling` and
`NFD and NFC spellings select the same lexicon entry`. The remaining three
(`capital sharp S`, `missing umlaut dots are not silently repaired`,
`StraBe is not rewritten to Straße`) passed immediately and are kept as
guardrails against over-normalization.

**GREEN.** `_normalizeForMatching` now folds `base + U+0308` for a/o/u (and the
capitals) to the same digraphs, and the literal-spelling preference compares a
German-composed form so NFC and NFD labels choose the same lexicon entry.
Combining marks other than the German diaeresis are left untouched, so they
break the match instead of being silently repaired. The raw label text is never
rewritten: `labelText` keeps the recognized spelling verbatim. Result: 5/5 new
tests pass, 325/325 recognition tests pass, no other test changed.

No other defect was demonstrated on the host; the OCR engine's own behaviour is
measured, not "fixed".
