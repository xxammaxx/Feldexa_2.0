section model" rule therefore holds, and this grouping is not a product feature.

Honest findings, not tuned away:

1. Equal counts never pass on wrong geometry. The comparison scores only
   declared pages, matches by exact lattice IoU, and a distance-only match is a
   geometry failure. No page in this corpus passes by count coincidence.
2. Duplicate candidates are reported, not hidden. Adjacent 11 pt checkboxes
   produce two near-duplicate candidates each (IoU 0.83-0.96, below the T055
   0.98 exact-duplicate threshold), so `checkbox-row` fails with five duplicates.
   The detector-side cause lives in T086B's file; the inventory surfaces it.
3. Faint print is invisible to the fixed 128 ink threshold. The `low-contrast`
   page (ink 170) yields zero candidates and three missing fields. That is the
   baseline gap the deferred contrast variant (T264C) must close against the
   frozen thresholds; it is not claimed as fixed.
4. A broken frame is not a field. The open bottom rule leaves three
   underline/whitespace candidates and no single region that matches the declared
   field, so the page fails.
5. A printed table cell is excluded only when its ink passes the 12 % gate. The
   corpus cell is drawn dense enough to pass it; an earlier 11.2 % hatch survived
   the gate as an extra candidate, which is why the corpus now draws a realistic
   printed cell. That is a corpus correction, not a threshold change.
6. Photo quality is measured on the photometric original. The shadow page reports
   `dynamicRange` 101 with `p05=154`, while flat pages report `dynamicRange` 0,
   proving the measurement is taken before any binarisation.
7. The `multiline` instance is real, not a unit-test-only claim: five 18 pt
   single-line fields fix the page's single-line reference height, so the 64 pt
   bounded area is typed `multiline` by both the geometric rule and the T053
   hint, and it matches with IoU 0.997 and correct type.
8. `signature` and `unknown` have **no** corpus instance. No detector cue emits
   `signature_area` on this corpus, and no detected region falls through every
   kind cue to `unknown`. `signature` has a unit test in
   `field_inventory_test.dart`; `unknown` is consumed by the structure-comparison
   tests but not exercised through the classifier's no-cue path. This corpus does
   not measure either kind, and the table above states that absence instead of
   implying coverage.

milliseconds, and the memory reading; the golden is committed and the host test

## 7. Limitations

- `SIMULATED` corpus only: declared labels, no OCR engine, and no scan artefacts
  beyond the synthetic shadow, low contrast, broken frame, and printed-cell
  cases. German umlaut handling is exercised only as verbatim label text
  (`Straße`); T263 owns the OCR-glyph qualification.
- No real authority form exists in the repository (no frozen corpus manifest), so
  real-form and holdout evidence are `ABSENT`.
- No Android, emulator, device, UI, editor, persistence, export, or accessibility
  evidence. The inventory is not wired into the app; it is an evaluation and
  diagnostics artifact by design.
- Numeric **value** semantics are a residual: negative, percentage, decimal
  comma, thousands separators, currency, leading zeros and numeric/date
  ambiguity exist here as *label* cases (typing/classification only). Nothing
  parses, validates or converts an entered value, and no precision/rounding
  claim is made. T264D and T263 own the value-level measurement.
- `signature` and `unknown` have no corpus instance (§5 rows 8); `signature` is
  unit-tested, `unknown` is consumed by structure-comparison tests but not by a
  classifier no-cue test, and neither may be read as corpus-qualified.
- Skew and DPI-variant handling are frozen in the policy but `UNAVAILABLE`,
  because the adaptive pass and the region-render decision are blocked.
- The evaluation-only section grouping is declared ground truth. It is not a
  detector input and not a product section model; a consumer must not treat a
  section id as a document attribute.
- Two lattice definitions coexist inside `geometry_metrics.dart`:
  `iou()` delegates to the T055 comparator, which rounds `x`/`y`/`width`/`height`
  independently, while `intersectionAreaPt2`/`unionAreaPt2`/`rectGapPt` round
  edges on the 1/8 pt lattice. For rectangles that are not exactly on the
  lattice the two can differ by one lattice unit, so `iou(a, b)` is not always
  `intersectionAreaPt2 / unionAreaPt2`. All comparisons here use `iou()`
  consistently (self-consistent matching) and detector rectangles are
  near-lattice, so no effect was observed; the "one exact definition" wording in
  the module header is stronger than the code and is corrected here rather than
  silently re-baselined.
- Frozen policy prerequisite `P1` in `tools/evaluation/adaptive-policy.v1.json`
  records `geometry_detector.dart` ownership as `NOT_MERGED`. That was true at
  freeze time and is stale now that T086B-P is integrated (PR #274,
  `2a1452b`/`7ccc175`). The policy is a frozen pre-run artifact and is **not**
  edited for that; the prerequisite must be re-read at T264C implementation
  time, not treated as still blocking.
- SC-001, SC-003, and SC-004 are not claimed; SC-002-style per-class reporting is
  delivered for this synthetic corpus only.

## 9. Reproducibility

1. Start from base commit `2a1452b378660940d70f99f0ead88da6a933da28` (the
   T264A/T264B commits are its children).
2. Run `flutter pub get` at the repository root for workspace resolution.
3. Put the Dart SDK on `PATH` (or set `DART=/path/to/dart`). The frozen scorer
   now **fails** instead of skipping when no Dart SDK is found, so a missing
   toolchain can never turn the byte-equality gate green.
4. Run `dart run tools/evaluation/field_inventory_baseline.dart --output run.json --snapshot snapshot.json`; expected `baseline written: pages=12 verdicts={pass: 6, fail: 6}` and exit `0`.
5. Run `cmp snapshot.json tools/evaluation/goldens/field-inventory-baseline.v1.json`; expected byte equality, and `run.json` `hashes.goldenSha256` must equal `sha256sum` of the golden.
6. Run `python3 -m unittest tools/evaluation/test_field_inventory_baseline.py`; expected 12/12 of that module (22/22 with `tools/evaluation/test_benchmark_recognition.py`).
7. Run `flutter test` in `packages/feldexa_recognition`; expected 382/382 at this
   base (371 before origin/main added the 11 T086B-P detector tests).
8. Compare `run.json` `hashes.corpusSha256`/`fixtureSha256`/`groundTruthSha256`
   with §2; they depend only on the corpus definition and must be identical on
   any host.
9. Clean up the two local JSON files; no device, emulator, or allocation is used.
