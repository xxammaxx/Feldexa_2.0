## 1. Scope

This report covers exactly T150 / issue #150: moving the page-strip
analysis-state vocabulary out of hard-coded Dart strings into the committed
German catalog/ARB surface, per FR-090 and the T043 residual. It changes the
catalog, the ARB, the generated localization, `page_strip.dart`, and one host
test; it changes no Kotlin source, Android resource, Gradle file, dependency,
`main.dart`, `page_view.dart`, `page_state.dart`, other feature, `tasks.md`,
checklist, constitution, plan, spec, or other task's file.

**Branch taken:** the catalog/ARB migration, not the recorded-owner-decision
branch. The four full German words and their four short visible forms already
existed verbatim in `page_strip.dart`, the catalog already owns every other
user-facing label, and no new wording had to be invented. Semantic key names
follow the §11.1 rule for non-code labels; each catalog §8 row is the norm.

What this run proves:

- The catalog §8 "Page analysis states" block is the normative German source for
  the four per-page states in their short and full forms.
- `app_de.arb` and the regenerated `AppLocalizationsDe` carry exactly those
  eight texts under the semantic keys `pageAnalysisPending`/`…Hint`,
  `pageAnalysisAnalyzing`/`…Hint`, `pageAnalysisComplete`/`…Hint`, and
  `pageAnalysisFailed`/`…Hint`.
- `page_strip.dart` reads all eight texts from `AppLocalizations`; no analysis
  state word remains as a Dart string literal. Visible text, semantics, layout,
  navigation, and the public API are unchanged.
- `german_strings_test.dart` now parses the eight catalog rows and compares each
  one character-for-character with the ARB value and the generated getter.
