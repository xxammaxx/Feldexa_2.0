## 1. Scope

This report covers exactly T040 / issue #40: the streaming encrypted source copy
and verified document commit in
`apps/feldexa_app/android/app/src/main/kotlin/de/feldexa/app/import/ImportService.kt`
and
`apps/feldexa_app/android/app/src/main/kotlin/de/feldexa/app/storage/EncryptedStore.kt`
(FR-004; FR-095/FR-096). The task makes the system's own protected copy the
document's source of truth and turns a staged aggregate into a listed document
only after preflight and a verified, atomic commit.

What this run proves:

- `EncryptedStore.stageSourceFromStream` reads the picked source in two bounded
  passes: a 64 KiB SHA-256/byte-count pass and a 1 MiB authenticated FXC1 write
  pass. It never materializes the whole source, never calls a whole-buffer API,
  and never creates a plaintext temporary file or plaintext copy.
- The staged source is read back chunk by chunk and verified against the
  streamed SHA-256 and byte count before any document can become visible. A
  mismatch (including a changed second pass or trailing bytes) fails closed and
  removes the incomplete aggregate.
- `EncryptedStore.openSourceReader` exposes a decrypting, seekable,
  chunk-bounded reader over the staged ciphertext. The production seam passes it
  to `PdfPreflight` through a `RandomAccessRead` adapter, so preflight never
  reads a plaintext file.
- After preflight succeeds, the initial revision and `meta.fx1`/`head.fx1` are
  committed exactly once. A duplicate visible aggregate is rejected without
  overwriting it; no second identity or initial revision is generated.
- `IMP-001`/`IMP-002`/`IMP-004`/`IMP-005` reject without a document, draft,
  template, or stored record. `IMP-006` succeeds with
  `pages[].unreadable = true`, `pageFailures`, and a persisted page failure.
- The committed document reads back through the protected store after the
  picked source is made unavailable; only `ContentResolver.openInputStream`
  (represented by the `PickedDocument` seam) is used, never a path conversion.
- Failure cleanup, cancellation, and the T038 lock-free repeated-cancel
  behaviour are preserved. A late cancellation after the verified commit does
  not delete the visible document.

### 5.1 Focused RED/GREEN and review corrections

The implementation followed a test-first cycle on the new store/source path:

- **RED before the feature code**: the new streaming/integration tests did not
  compile against the T038 `SourceStaging(ByteArray)` seam and the missing
  `stageSourceFromStream`/`openSourceReader` methods; the production test task
  was therefore not run as a meaningful RED. The first GREEN focused run
  exposed four test-authoring defects (an integer cast, a double comparison, a
  racy cancel claim, and a test expecting a discarded aggregate after a
  verification mismatch). The implementation was corrected to delete the
  incomplete aggregate on every commit failure after the visible-meta check.
- **Lock-order correction**: a cancellation test hung because the service's
  post-preflight `checkCancelled()` took the operation-handle lock while the
  facade cleanup held that lock waiting for the staged lifecycle lock. The
  implementation now uses a lock-free `isCancellationClaimed` accessor and
  records cleanup failures outside the lifecycle lock; the two cancellation
  tests pass. This is declared as a minimal seam in `FeldexaPlugin.kt`.
- **Final GREEN**: the full suite and `assembleDebug` pass on
  `f870eca`; see §4.
- **Scope correction**: the initial implementation used `Dokument` as the
  fallback title when the provider supplied no display name. Because T041 owns
  German import/UI wording, correction commit `013daf5` uses the neutral
  `PDF` token instead and adds no German text. The full suite and
  `assembleDebug` were re-run on the correction tree: 345 tests / 17 suites /
  0 failures, `BUILD SUCCESSFUL`; the APK size remains 231,177,848 bytes.

### Observed behaviour

- **Streaming shape:** a 2,097,152 + 12,345-byte source records multiple
  `HASH` chunks, each ≤ 65,536 bytes, and multiple `WRITE` chunks, each
  ≤ 1,048,576 bytes. The store contains exactly one `src/<sourceId>.fxc`, no
  `tmp/` entry remains, and no store file contains the source's `%PDF-`
  plaintext marker.
- **Seek/read:** `openSourceReader` returns the full source, a 32-byte read
  crossing the first 1 MiB boundary byte-identically, and a three-byte tail
  followed by `-1`.
- **Verification and cleanup:** a second pass with one changed byte or one
  trailing byte fails with `InvalidDataException` (`SAVE-007` storage
  vocabulary) and leaves no aggregate. A wrong expected hash at commit fails
  with `CorruptDataException` (`SAVE-003`) and leaves no visible document.
- **Real preflight:** a real 3-page synthetic PDF commits; a real
  password-protected PDF yields `IMP-001`; a 50% truncated PDF yields
  `IMP-002`; random non-PDF bytes yield `IMP-004`; a page with no usable
  MediaBox yields a successful `IMP-006` commit with one unreadable page.
- **Source of truth:** after the integration test disables the picked
  `PickedDocument`, `EncryptedStore.loadDocument` still returns the exact PDF
  bytes and the document remains listed readable. The picked content was opened
  exactly twice (hash and write passes), both read-only.
- **Duplicate/atomicity:** a second import with the same document id is
  `SAVE-006`; the original meta, revision, head, source bytes, and the single
  revision file are unchanged.
- **Cancellation:** cancellation during preflight removes the staged aggregate
  and returns `PLT-004`; a late cancel after a verified commit leaves the
  document visible and records no cleanup failure. The T038 facade
  late-cleanup/repeated-cancel regressions still pass.
- **Build:** `assembleDebug` succeeds; the debug APK is 231,177,848 bytes.

## 7. Limitations

- `NONE` is not a runtime evidence class. No Android runtime, emulator, device,
  SAF, `ContentResolver`, Keystore provider, MethodChannel, viewer, OCR, field
  detection, export, or user journey was executed. This report does not claim
  any of them.
- The tests use the real `EncryptedStore` with real AES-GCM and a temporary
  filesystem, and the real `PdfPreflight` with synthetic in-memory PDFs, but
  the T025/T026 test Keystore backend is a JVM double. Android Keystore
  behaviour is not exercised here.
- `stageSourceFromStream` reads the picked content twice because the FXC1 AAD
  needs the final plaintext length and chunk count before the first chunk can
  be authenticated. The source is opened read-only both times via the
  `PickedDocument` factory; a provider stream that cannot be reopened fails
  closed as `IMP-002`. No plaintext or intermediate ciphertext temp file is
  created.
- The `store.stageSource` channel bridge (ByteArray input) remains the
  materialized API for the synchronous `store.stageSource` channel method. T040's
  streaming path is `EncryptedStore.stageSourceFromStream`, used by
  `ImportService`; the channel method is not a streaming claim.
- Preflight uses PDFBox `MemoryUsageSetting.setupMainMemoryOnly()` and may hold
  the staged plaintext in memory while parsing; that is a preflight property,
  not a staging claim. The encrypted staging path itself is chunk-bounded.
- T039 reports null geometry for a page whose structure could not be read. The
  persisted `Page` model and the channel page shape still require a positive
  box, so such an unreadable page is persisted with a deterministic 1x1
  placeholder geometry, `unreadable = true`, and its `IMP-006` failure. The
  placeholder is never claimed as the original page geometry; T042/T044 must
  treat an unreadable page as non-renderable content and must not present the
  1x1 box as a real page size.
- A cancellation that wins after the final `meta.fx1` promotion cannot remove
  the now-visible document and may still yield the facade's `PLT-004` terminal
  result. The document is complete and verified, not partial; no user data is
  deleted. This residual race is narrower than the T038 interrupted-first-cancel
  window and is not claimed as fully eliminated.
- The 80 MiB cap signal is `IMP-007`; T045 owns the exact ARB/catalog wording
  verification. No German text was added or changed here.
- `import.verifySource` and `import.discardStaged` remain `PLT-001`
  unsupported; T040 does not invent their wire shape.
- No release build, R8/minify run, APK install, emulator boot, or runtime test
  was performed. No Android runtime evidence is claimed.
- `tasks.md` was not edited, so the T040 checkbox remains for the
  coordinator/integrator.
- The custom `checklists/precision-testability.md` has 36 unchecked,
  reviewer-owned items. It was not modified and is not presented as passed.
- This report omits its own byte size and SHA-256, and the implementation and
  report commit object ids, by construction. Those values are in the external
