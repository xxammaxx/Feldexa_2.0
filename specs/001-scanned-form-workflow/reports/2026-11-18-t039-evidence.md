and encryption detection in

### 5.1 Review correction — bounded page count

Review A found that `PdfPreflight` read `open.numberOfPages` and used it
directly for `ArrayList<PdfPreflightPage>(pageCount)` and the page walk, with
only a `pageCount <= 0` guard. The implementation now has one named constant,
`MAX_PAGE_COUNT = 100`, based on `plan.md` §Scale/Scope ("typical 1–10 pages
... supported up to 100 pages") and `contracts/storage-format.md` §6 ("max
pages: 100"). The single reported count is checked before any per-page
collection or page access; an over-limit count is rejected with the existing
`IMP-004` / `import.unsupportedStructure` / `notPdf` mapping and the unchanged
six-field `details()` shape. No new catalog code, machine key, German text,
dependency, Gradle setting, or password path was added.

The German wording for an over-scale document (the existing `IMP-004` sentence
"Diese Datei ist kein unterstütztes PDF ...") is a T041/owner wording question,
exactly like the two existing deferred-key notes; this report does not invent
or change German text.

### Observed behaviour

- **Geometry:** the 3-page fixture returns page 0 as A4 `595.28 × 841.89`,
  CropBox `(10, 20, 560, 790)`, rotation `0`; page 1 as A5 landscape
  `595.28 × 419.53`, CropBox equal to MediaBox, rotation `90`; page 2 as
  `(10, 20, 300, 400)`, CropBox `(20, 30, 250, 380)`, rotation `270`. Page 2's
  MediaBox is not swapped despite rotation 270. An oversized CropBox is clipped
  to the MediaBox. An inherited `/MediaBox` on the page tree is honored without
  PDFBox's Letter fallback.
- **Encryption:** a real PDFBox synthetic PDF with a non-empty user password
  yields `IMP-001`/`import.passwordProtected`/`importRejected`; one with an
  empty user password loads in PDFBox but is still rejected as
  `IMP-001`/`import.unsupportedEncryption`; an unsupported security-handler
  failure is also `IMP-001`/`import.unsupportedEncryption`. No password argument
  exists in the production API, and no test password appears in any failure
  message or details value.
- **Truncation:** cutting a valid 3-page PDF at 50%, 90%, or 99% yields
  `IMP-002`/`import.unreadable`/`unreadable` without calling the PDFBox loader,
  even though PDFBox 2.0.27 can otherwise load the 50% file as a one-page
  document. A bare `%PDF-` header is `IMP-002`; empty and headerless bytes are
  `IMP-004`/`import.notPdf`/`notPdf`.
- **Damage/unsupported/unknown:** an injected damaged-parse `IOException` maps
  to `IMP-002`; an injected unsupported-feature `IOException` maps to
  `IMP-004`/`import.unsupportedStructure`/`notPdf`; an injected unexpected
  `IllegalStateException` maps to `IMP-005`/`import.unknown`/`internalError`
  without its message or path appearing in the result. A zero-page PDF and a
  document whose every page has no usable MediaBox are `IMP-004`; a document
  whose every page throws while reading is `IMP-002`.
- **Partial pages:** one unreadable page in a 3-page document produces
  `PdfPreflightSuccess` with `pageCount = 3`, exactly one `pageFailures` entry,
  `pages[1].unreadable = true`, no geometry for that page, and unchanged
  geometry/order for pages 0 and 2. The failure category is
  `unsupported_structure` for a missing MediaBox and `unreadable` for a page
  read exception; both carry `messageKey = IMP-006`.
- **Cleanup and privacy:** the tracking `PDDocument` is closed after success
  and after a whole-document page failure; the caller-owned tracking reader is
  not closed on success or rejection. Failure details contain exactly
  `schemaVersion`, `category`, `retryable`, `pageIndex`, `fieldCount`, and
  `durationMs`; an injected clock returns `42` ms. Failure messages match the
  closed machine-key shape and contain no `.pdf`, slash, backslash,
  `content://`, or synthetic password text.
- **Page-count bound:** a reported count of 10,000 or 101 is rejected as
  `IMP-004` before any page access; a real 101-page document is rejected; a real
  100-page document is accepted with all 100 indices and first/last geometry
  present. The bound is applied before `ArrayList` and the page walk.
- **Build:** `assembleDebug` succeeds and the debug APK contains
  `Lde/feldexa/app/pdf/PdfPreflight;`. `flutter analyze` reports no issues.

## 7. Limitations

- `NONE` is not a runtime evidence class. No Android runtime, emulator, device,
  SAF, staged decrypting reader, Keystore, MethodChannel, viewer, OCR, field
  detection, export, or user journey was executed. This report does not claim

  validator. Damage confined to page content streams, or a truncation that
  leaves a complete earlier revision with `%%EOF`/`startxref`, can still load.
  Real damaged-file integration coverage remains T046.

  page walk, close path, and result classification remain in the tested code.
