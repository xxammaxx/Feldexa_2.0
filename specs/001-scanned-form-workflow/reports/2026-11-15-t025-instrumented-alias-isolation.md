called `deleteAllAggregateAliases()`, which enumerated the Keystore and deleted

## 5. Results

### 5.1 Finding and correction

The reviewed test called `deleteAllAggregateAliases()` from `setUp` and
`tearDown`; that helper iterated `keyStore.aliases()` and deleted every alias
whose name started with `feldexa.doc.v1.` or `feldexa.tpl.v1.`. Under the
production application id this is destructive to real data keys.

The corrected test uses [IsolatedTestBackend], a test-only `KeystoreBackend`
decorator. It maps every logical T025 alias to:

```text
feldexa.test.v1.<random per-test-instance UUID>.<logical alias>
```

The real production `AndroidKeystoreBackend` is still used underneath, so the
real Keystore AES-GCM behavior and lifecycle are exercised, but the physical
aliases cannot collide with production aliases. `listAliases()` reports only
logical aliases tracked by the decorator, so the service's own orphan sweep can
only see test-owned aliases.

Cleanup is exact-only:

- `createdAliases` records each physical alias generated by
  `generateAesKey`;
- `deleteCreatedTestAliases()` iterates that tracked set, skips anything not
  under the test namespace, and calls `delegate.deleteAlias(physical)` only for
  those exact aliases;
- there is no `keyStore.aliases()` call and no production-prefix match in the
  test;
- `validateIsolation()` runs in `setUp` before any Keystore operation and
  checks that the namespace starts with `feldexa.test.v1.` and that a mapped
  alias differs from the logical production alias.

The two isolation regressions are:

1. JVM static guard `InstrumentedKeystoreAliasSafetyTest` (3 tests) reads the
   instrumentation source and fails if `deleteAllAggregateAliases`,
   `keyStore.aliases()`, production-prefix startsWith checks, or direct
   `keyStore.deleteEntry` calls are reintroduced. It also checks the unique
   namespace and exact-tracked cleanup body.
2. Android `cleanupDoesNotDeleteForeignTestAlias` creates a foreign alias under
   a different `feldexa.test.v1.` run namespace, invokes the backend cleanup,
   asserts the foreign alias still exists, and then explicitly deletes that
   test-owned alias in `finally`.
