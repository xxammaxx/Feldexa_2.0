### Corrected expectation model

Each expectation declares exactly one state per adapter:

- `satisfied` — the check runs and any violation throws
  `ImportConformanceFailure`, which fails the runner.
- `notCovered` — the runner skips it with a mandatory reason; it is never a
  pass and never counted as protection.
- `nonConforming` — the runner registers a deliberate failure; it can never be
  reported as a pass.

The generic success expectation now requires only the port-level invariants:
one visible document, no template/artifact, one staged source, the documented
`ImportedSource` shape, and a source hash that matches the picked bytes. It no
longer asserts any revision count, so both a port that commits the initial
revision and the current T028 split flow pass it.

The named `initial-revision-committed-and-verified` expectation requires at
least one committed revision, a present head, and a verified source hash. It is
the only expectation that owns that requirement.

The expected evidence class is derived from the subject's own
`CapabilityDescriptor`; `_assertIntegrity` compares the `SourceIntegrity`
evidence class and label with that descriptor. A real Android adapter therefore
passes with `EvidenceClass.none`. The mandatory `SIMULATED` assertion lives
only in `evidence-labelled-simulated`, which applies only to a simulated
adapter.

### T028 initial revision: factual finding and decision

The maintainer's assumption that the shipped T028 adapter already commits one
revision is **incorrect for the current code**. `simulated_import_adapter.dart`
creates the aggregate with `head: null` at `:206` inside the
`putDocument(SimulatedDocumentRecord(...))` block at `:199-209`;
`SimulatedDocumentRecord` defaults `revisions` to an empty map at
`simulated_backend.dart:104-107`. The later `store.createDocument` fills the
revision and head (`simulated_store_adapter.dart:211-220`).

**Decision:** T028 was not changed to commit an initial revision during import.
Doing so would set `existing.head != null` and make the documented
import→`createDocument` flow throw `SimulatedConcurrentWriteException` at
`simulated_store_adapter.dart:179-183`; the split is deliberate in T028 and
matches the channel flow where `store.stageSource` precedes
`store.createDocument`. The named expectation therefore remains `notCovered`
with the clause and owner in the reason above. It is a visible gap, not a
weakened assertion or a pass.

### T028 `SAVE-003` staged-integrity correction

`contracts/storage-format.md` §3.1 step 3 and §5 require
`CorruptDataException` (`SAVE-003`) when a staged read-back hash or
authentication check fails; `IMP-002` is for unreadable input. The old T028
branch at `simulated_import_adapter.dart:177-182` threw
`ImportRejectedException(unreadable)` (`IMP-002`). It now removes the staged
source and throws `CorruptDataException` at `:185`.

The minimal fault seam is `SimulatedBackend.corruptNextStagedReadBack()` at
`simulated_backend.dart:406`, which flips the returned read-back copy once at
`:419-423` without changing the stored bytes. The affected T028 test added is
`simulated_import_test.dart:321` (`staged read-back damage maps to
CorruptDataException SAVE-003`). No existing T028 test was modified or removed;
all 19 import tests and the full simulated suite pass. The historical
`reports/2026-11-15-t028-evidence.md` was not rewritten.
