## 1. Scope

This report covers **T037 only**: the two new contract-test files

The port suite pins the documented `DocumentImportPort` contract
(`contracts/ports.md` §1, §2.1, §2.10, §3, §4; `contracts/platform-channel.md`
§3 and §12): accepted single-page and five-page image-only sources with page
geometry, the canonical typed rejections (`IMP-001`, `IMP-002`, `IMP-004`,
`IMP-005`, `IMP-007`), cancellation (`IMP-000`), storage exhaustion
(`SAVE-001`), a failed staged write (`SAVE-003`), no record after a rejection,
source immutability plus read-back hash verification, the typed error taxonomy,
and evidence labelling.

The core suite pins the core half of `spec.md` FR-001, FR-002, FR-004, FR-009,
and FR-010: `SourceFileRef` bounds and display-only name rules,
`SourceIntegrityState`, `PageFailure` for the `IMP-006` partial case,
`PageGeometry` media/crop/rotation preflight invariants, and the canonical-JSON
save/reopen round trip of the imported source reference.

This suite does **not** implement the Android import service or PDF preflight,
and it proves no Android runtime behaviour. The port-level results are produced
by a deterministic in-file double, not by the T028 adapter and not by Android
code; those results are `SIMULATED` where the double labels them so.

## 7. Limitations

- `NONE` is not a runtime class. This report cannot satisfy an import,
  recognition, secure-storage, permission, or PDF-handling acceptance gate.
- No Android, emulator, or device evidence exists for T037. The tests do not
  open a SAF picker, parse a real PDF, detect real encryption, touch the
  Keystore, or verify pixel fidelity.
- The port contract is proven against a deterministic in-file double, not the
  T028 simulated adapter: the dependency rule forbids `feldexa_ports` from
  depending on `feldexa_adapters_simulated`, and no dependency was added. This
  is by design, not a missing assertion.
- `import.discardStaged` is a platform-channel-internal cleanup method, not a
  Dart `DocumentImportPort` method. The suite pins the observable cleanup rule
  through the double (a failed read-back removes the staged source) rather than
  a non-existent Dart method.
- The core suite exercises `SourceFileRef`, `SourceIntegrityState`,
  `PageFailure`, and `PageGeometry` directly. It does not exercise the full
  `Document` aggregate or a real persistence layer; those remain with their own
  suites.
- Check 6 (repo-root simulated run) failed on the pre-existing
  `Directory.current` assumption in `simulated_boundary_test.dart`; check 7
  passed from the package directory. No simulated-adapter source changed.
- The new report is not listed in `reports/README.md` §9 because that file is
  outside T037's allowed write scope. The orchestrator must append the index
  row; the evidence validator's index check would otherwise report it.
- The pre-existing `apps/feldexa_app/android/gradlew.bat` line-ending change
  was left untouched and is excluded from the candidate.
- This report omits its own artifact row and hash by construction
  (README §4.1).
