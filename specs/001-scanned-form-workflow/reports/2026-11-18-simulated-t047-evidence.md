## 1. Scope

This report covers exactly T047 / issue #47: the new browser import journey in
`apps/feldexa_app/integration_test/web_import_test.dart` and its single
committed entrypoint helper. The journey runs the German import flow through
the T028 deterministic `SIMULATED` import adapter over the committed synthetic
fixture catalogue, in a real Chrome browser, and asserts the supported import
result, three typed rejections, cancellation, and the `SIMULATED` evidence
labels that the current code exposes.

What this run proves:

- Chrome loads and verifies the committed catalogue `fixtures-1.0.0`: seven
  fixtures, four valid and three failure fixtures, with every SHA-256, byte
  size, page geometry, typed rejection code, and expected-OCR shape checked by
  `SimulatedFixtureCatalog.parse`.
- `sf-003` imports through the T028 `SimulatedDocumentImportAdapter` and the
  app-level `ImportFlow`: five pages in catalogue order, rotations
  `0/0/90/180/270`, the catalogue's display sizes, display name `sf-003.pdf`,
  the catalogue SHA-256 and byte size, staged bytes identical to the fixture,
  one document aggregate, a readable `verifySource`, and
  `EvidenceClass.simulated` on the result.
- `sf-protected`, `sf-truncated`, and `sf-not-a-pdf` reject with the exact
  German `IMP-001`, `IMP-002`, and `IMP-004` message and recovery text from
  `AppLocalizationsDe`, the correct password-exactness flag, no created
  document, no staged source, and no `createDocument` call (FR-009). Picker
  cancellation is an `ImportCancelled` outcome with no message and no stored
  record.
- The app's Web registry accepts a ten-port adapter set whose six T028
  descriptors are `web.sim.*.v1` with `EvidenceClass.simulated`, reports
  `hasSimulatedCapabilities`, and still fails the release guard with `SIM-001`.
- The committed German `simulatedBanner` and `simulatedBannerContext` strings
  are resolvable through the generated localizations and render in Chrome. The
  test does not implement T129's production banner wiring; it proves the
  string surface only.

What this run never proves:

- No Android runtime, emulator, physical device, SAF picker, MethodChannel,
  Android Keystore, FXC1 encrypted store, PDFium on Android, ML Kit OCR,
  PDFBox, print fidelity, or APK was used. No command in this report targets an
  Android device or emulator.
- The simulated adapters are deterministic substitutes, not the Android
  implementations. Their in-memory store provides no confidentiality,
  integrity, or durability guarantee.
- The journey is not the complete editor journey of T128. It covers import and
  the import gate only; editing, field suggestions, overlays, export, and
  accessibility traversal remain other tasks.
- The `simulatedBanner` check renders the committed string in a minimal
  localized surface. It does not prove that the production shell displays a
  banner; T129 owns that wiring.
- No real browser file picker is driven. The T028 fixture picker is the
  deterministic seam; that is the documented Web development substitute.
- No performance, rendering-quality, or acceptance claim is made.

## 7. Limitations

- **Browser only.** The run proves Chrome behavior with simulated adapters,
  not Android runtime behavior, SAF, Keystore, FXC1 storage, PDFium on Android,
  ML Kit, PDFBox, print, or device acceptance.
- **Simulated storage.** The in-memory backend is not encrypted and makes no
  confidentiality, integrity, or durability claim. A “no stored record”
  assertion means the simulated backend exposed none; it is not an Android
  store assertion.
- **No real file picker.** The deterministic fixture queue is the T028
  development seam. No system file chooser, URI permission, or provider stream
  is exercised.
- **Partial journey.** Import, rejection, and cancellation are covered; the
  full Chrome editing journey of T128, the production banner wiring of T129,
  viewport/accessibility checks of T131, and geometry parity of T132 remain
  open.
- **Banner surface.** The test renders the committed banner string in a minimal
  localized widget; it does not prove that the production shell displays it.
- **Entrypoint helper.** The browser test must be run through the committed
  `test/web_import_browser_entry_test.dart` symlink because
  `flutter test --platform chrome` cannot compile a file outside `test/`
  directly. A symlink is portable on the supported Linux host but is not a
  journey implementation.
- **Loopback fixture delivery.** The only HTTP traffic is the committed static
  fixture mirror on loopback. No product backend, external host, or internet
  service is contacted.
- **No performance claim.** No timing, throughput, or three-second claim is
  made.
- **No Android labelling.** Nothing in this report is an `EMULATOR` or
  `DEVICE` result, and no browser result is attributed to Android.
