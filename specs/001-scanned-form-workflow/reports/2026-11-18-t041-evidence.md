What this run proves:

- Every import code the platform can surface has a German presentation resolved
  through `AppLocalizations`: `IMP-001`…`IMP-005`, `IMP-007`, `IMP-000`
  (picker cancel), `PLT-004` (cancellation), and the import-reachable storage
  codes `SAVE-001`, `SAVE-002`, `SAVE-003`, `SAVE-005`, `SAVE-006`,
  `SAVE-007`, and `SAVE-008`. `IMP-006` is handled on the success path as the
  partial-import warning.

  read from the committed ARB through `AppLocalizations`; the exact catalog
  text itself remains verified by the unchanged `german_strings_test.dart`.
- An unknown or unclassified failure uses `IMP-005` semantics (“actual cause
  unknown”) and never claims password protection (FR-007).
- Only a positively classified `import.passwordProtected` failure sets the
  password-exactness flag. The distinct `import.unsupportedEncryption` finding
  is presented under the single committed `IMP-001` text with the flag false,
  which records the open T041/owner wording question instead of silently
  changing the catalog or ARB.
- Rendered messages and recovery guidance contain no `IMP-`/`SAVE-`/`PLT-`
  code, no path, no URI, and no document title (catalog tone rules).

  usable and is created.

  creation. The sealed outcome carries no document-creation input for those
  cases, the candidate type has a library-private constructor, and the flow
  invokes the creation callback exactly once only after `pickAndImport`

## 7. Limitations

- `NONE` is not a runtime evidence class. No Android runtime, emulator, device,
  SAF picker, channel, Keystore, storage, viewer, OCR, field detection, export,
  or user journey was executed for T041.
- The mapper is a pure Dart translation layer. It does not wire the channel,
  render a dialog, navigate, or persist anything; T040/T042 and later tasks own
  those surfaces.
- The rejection gate proves that the provided flow never calls the creation
  callback on rejection. Real document creation does not exist yet; the flow
  accepts an injected `ImportDocumentWriter`, and persistence behaviour remains
  a later task's evidence.
- FR-007 is handled truthfully but one wording question remains: the catalog
  has a single `IMP-001` sentence that names password protection, while T039
  also reports `import.unsupportedEncryption` under `IMP-001`. T041 presents
  that case with the committed text and sets `passwordProtectionConfirmed` to
  false so the screen owner can apply an owner-approved wording later. The
  catalog and ARB were not changed, and no replacement German text was
  invented.
- The catalog defines the `{pages}` placeholder but not its grammatical form.
  T041 fills it with a comma-separated ascending list of 1-based page numbers
  and invents no German noun. A wording such as „Seite 2“ or „Seiten 2 und 4“
  would need its own catalog/ARB key and is left as a wording question for the
  `IMP-006` surface (T044/owner).
- `SAVE-006` is mapped to the committed `save006` sentence for the persistent
  conflict case. The catalog's automatic single retry is an orchestration
  behaviour, not part of this translation layer; no retry loop is claimed
  here.
- The mapper never inspects a path, URI, title, or document content. It cannot
  prove what a future adapter puts into an untrusted `message` string; it uses
  only the stable `code` and the typed `ImportRejectedException.kind`, and
  never renders `message`.
- No Kotlin/Android file was changed, so `./gradlew` was not run. Conditional
  check C1 is `ABSENT` and C2 is `UNAVAILABLE`; neither is presented as a pass.
- The pre-existing dirty `apps/feldexa_app/android/gradlew.bat` line-ending
  change is unrelated to T041 and was left untouched. The report records the

- No push, PR, merge, rebase, reset, tag, or branch publication occurred.
- `tasks.md` was not edited, so the T041 checkbox remains unchanged for the

- This report omits its own byte size and SHA-256, the implementation commit
