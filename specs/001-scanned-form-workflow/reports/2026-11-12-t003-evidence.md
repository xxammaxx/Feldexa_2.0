## 6. Pre-existing checkout line-ending finding (`android/gradlew.bat`)

The file `apps/feldexa_app/android/gradlew.bat` is reported as modified immediately after checkout and is **not** a T003 change. It was preserved byte-for-byte; T003 did not stage, restore, renormalize or discard it.

Evidence:

```text
.gitattributes: *.bat text eol=crlf whitespace=cr-at-eol
HEAD blob:                 aec99730b4e8fcd90b57a0e8e01544fea7c31a89
index blob:                aec99730b4e8fcd90b57a0e8e01544fea7c31a89
worktree raw hash:         aec99730b4e8fcd90b57a0e8e01544fea7c31a89
worktree filtered hash:    8a0b282aa6885fb573c106b3551f7275c5f17e8e
git diff --numstat:        90  90  apps/feldexa_app/android/gradlew.bat
git diff --ignore-space-at-eol --stat: (empty)
cmp(index blob, worktree): 0 (byte-identical)
git check-attr:            text=set, eol=crlf, whitespace=cr-at-eol
core.autocrlf/eol/safecrlf: not configured
```

Diagnosis: the committed/index blob contains CRLF. Because `.gitattributes` marks `*.bat` as `text`, Git applies the clean filter to the worktree before comparing it with the index; the clean filter normalises CRLF to LF. The index blob is still CRLF, so `git diff` sees every line as changed and reports the filtered blob `8a0b282…` as the new side, even though the raw worktree bytes are identical to the index (`cmp` exit 0). `git diff -w` and `--ignore-space-at-eol` are empty because there is no content change. The file was introduced by T002 commit `6507615` ("commit Gradle wrapper"), so this is a one-time normalization defect at the base revision, not a worktree mutation.

Correct fix, **not performed by T003** (it is a repository-maintenance change, not a dependency task): run `git add --renormalize -- apps/feldexa_app/android/gradlew.bat` and commit the LF-normalized blob once. With `eol=crlf`, the worktree stays CRLF and future checkouts are clean. Do not `git checkout --` the file as a "fix"; that does not change the committed CRLF blob. If the project instead wants CRLF stored in the blob, the attribute would need to be `-text` for that path, which contradicts the current `.gitattributes` intent.
