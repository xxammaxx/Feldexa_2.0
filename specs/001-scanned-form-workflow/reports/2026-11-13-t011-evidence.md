## 6. What the toolkit provides

### 6.1 Fake clock

`FakeClock` matches the `ClockPort` method shape
(`DateTime nowUtc()`) from `contracts/ports.md` §2.8 without importing the
not-yet-implemented ports package. It starts at the Unix epoch unless given an
initial instant, normalises local input to UTC, counts reads, advances only on
explicit `advance`/`advanceTo`, rejects negative/backwards advances, and exposes
an explicit `setUtc` rewind. `reset` returns to the creation instant.

### 6.2 Fixture loader and path safety

`FixtureCatalog` parses and validates the committed T009 catalogue before any
bytes are returned:

- schema version 1 and a non-empty catalogue version;
- `evidenceClass` must be exactly `SIMULATED`; `EMULATOR`, `DEVICE`, and `NONE`
  are rejected with an explanation;
- synthetic rights: no third-party content, no personal data, rights cleared;
- dev-only delivery: `flutterAssetsDeclared` must be false;
- fixture count, unique ids, id/path agreement, declared delivery directories,
  lowercase 64-hex SHA-256, positive size, page count/index/geometry/rotation;
- role/status consistency and the required `IMP-001`, `IMP-002`, `IMP-004`
  codes for the three failure fixtures;
- expected-OCR references for valid fixtures, forbidden on failures, with
  matching page/block counts;
- ground truth present only for valid fixtures.

**Path inputs** are treated as untrusted catalogue data. Every value that can
reach a source is checked with `validatePortableRelativePath` (or the Web-base
variant) before use:

| Catalogue input | Validation |
| --- | --- |
| `delivery.canonicalDevDirectory`, `webDirectory`, `corpusDirectory` | Portable relative path; backslash, drive/ADS colon, control, absolute, `.`/`..`, empty/trailing segment, trailing dot/space rejected |
| `delivery.webBaseUrl` | Site-absolute; rejects `//host`, queries, fragments, and every portable-path violation |
| `generator.path` | Portable relative path |
| `fixtures[].path` | Must equal `<id>.pdf` and pass the portable rule |
| `fixtures[].assetPath`, `webPath`, `corpusPath` | Must equal the declared safe directory + file, then pass the portable rule |
| `fixtures[].expectedOcr.path` | Must equal `<id>.expected-ocr.json` and pass the portable rule |
| `fixtures[].synthetic.generator` | Portable relative path |
| `FixtureSource.read(...)` paths | Same portable rule through `validateFixturePath` |

`FixtureLoader` then checks the actual bytes: declared size, SHA-256 against the
catalogue pin, and the documented shape (`%PDF-` header and `%%EOF` trailer for
valid/encrypted fixtures; header without trailer for the truncated fixture; no
PDF header for the text fixture). Expected-OCR JSON is validated for schema,
fixture id, German language, `SIMULATED` class, page count, and total block
count.

`FixtureCheckout.rootDirectory` is a trusted caller argument, not catalogue
data; the catalogue only contributes the checked relative delivery directories.

### 6.3 Fault hooks

`FaultKind` covers storage-full (`SAVE-001`), keystore unavailable/corrupt key
(`SAVE-002`), short write/fsync failure/write interruption (`SAVE-003`), and
export failure (`EXP-002`). `FaultRule` declares a point, kind, one-based
`startsAt`, and `times` (one-shot by default, `null` for every matching call).
`FaultInjector` checks a point, counts calls, throws `InjectedFault` with a
content-free message, records calls/injected faults, and offers synchronous and
asynchronous wrappers. Rules are validated (empty point, bad start/count,
duplicate point/call) and can be armed, disarmed, or cleared.

This is the generic hook layer, not T036's concrete
`FaultInjectingStore`/adapter harness in `lib/src/faults.dart`. T036 remains
open and will consume these primitives once the ports exist.

### 6.4 Evidence labels

`EvidenceClass` encodes `NONE`, `SIMULATED`, `EMULATOR`, and `DEVICE`.
`EvidenceLabel` binds a class to a surface (host VM, Chrome, emulator, device)
and `EvidenceLedger.requireSeparated()` rejects a report that merges `SIMULATED`
with `EMULATOR`/`DEVICE`. The label types are metadata: using the toolkit never
upgrades a run's class.

## 12. Historical T010 evidence checker

The old checker hashed working-tree files against T010's pinned rows. When a
later task changed `tasks.md` (T011 `[x]`), a legitimate historical record was
reported as a failure. This revision changes the checker, its regression test,
and the evidence README; the T010 report and its external attestation were not
rewritten.

`tools/evaluation/check_evidence_docs.py` now verifies artifact rows against
committed Git trees:

1. It parses the rows, rejects paths that escape the repository, and skips
   local `.dart_tool/` logs as before.
2. It verifies the rows at `HEAD`.
3. If `HEAD` no longer matches, it searches commits reachable from `HEAD` for a
   revision where every recorded size and SHA-256 matches and the report exists
   there. It accepts only that revision and prints
   `PASS historical artifacts: <sha>`.
4. `--revision <commit>` pins the revision explicitly; a mismatch fails.
5. `--attestation-ref`/`--attestation-file` makes the attestation candidate
   authoritative. Report self-hash and changed files are verified at that
   commit even when it is not `HEAD`; a missing candidate, changed-file
   tampering, or a conflicting `--revision` fails.
6. There is no fallback to the working tree: a changed file that no recorded
   revision ever contained still fails.

## 13. Limits

- The fault hooks are generic primitives. They do not prove that any real
  storage, Keystore, or export adapter recovers correctly; that requires the
  concrete harness and adapter tests (T036 and later).
- The fixture loader checks declared size, SHA-256, and coarse PDF shape. It is
  not a PDF parser, decryptor, or artifact verifier; T105/T143 own independent
  artifact verification.
- Path validation rejects unsafe catalogue strings before a source sees them.
  It does not resolve symlinks inside a trusted checkout root; the root itself
  is a caller-supplied test location, not catalogue data.
- The fixture catalogue's `groundTruth` is exposed as deeply immutable raw JSON
  until `feldexa_core` owns the typed model (T015/T018).
- SHA-256 in the toolkit is fixture-integrity tooling, not a security boundary
  and not a substitute for the encrypted storage design.
- The gate pass is qualified: the browser integration layer is still absent,
  and no `EMULATOR` or `DEVICE` run occurred. No Android acceptance claim is
  made.
- Historical verification needs the recorded revision in the clone's history.
  A shallow clone that omits it fails instead of guessing; fetch the history or
  provide `--revision`/the attestation ref.
- The checker validates committed trees. An uncommitted working-tree edit is
  not evidence and cannot be used to satisfy a historical row.
- This report is execution provenance and self-evidence, not an independent
  approval.
