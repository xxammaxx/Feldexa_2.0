## Finding (before the fix)

`AndroidDiagnosticsClient.event()` kept every `String`, `num`, and `bool`
scalar verbatim while its class documentation claimed titles and paths were
"dropped rather than risking a content leak". That inverted the
`contracts/ports.md` §2.9 whitelist (enums, counts, durations, error codes)
and left FR-081's exclusion duty unenforced. The old privacy suite (5/5) was a
characterization of that behavior, not a contract check: it asserted that
`event()` does not throw, with no read access to the buffer.

## Fix

`packages/feldexa_adapters_android/lib/src/android_system_clients.dart`:

- `event()` is fail-closed on three lanes:
  - **Event code**: only a dotted lower-camel identifier from an explicit
    namespace allowlist (`save`, `store`, `export`, `import`, `recognition`,
    `editor`, `review`, `template`, `analysis`, `lifecycle`, `diagnostics`,
    `operation`, `raster`, `delivery`, `app`, `probe`), at most 64 characters,
    without a file-extension segment. Anything else drops the whole event.
  - **Field name**: only a single lower-camel/snake identifier, at most 64
    characters, without a file-extension segment. Anything else drops that
    entry.
  - **Scalar value**: only an `Enum` (stored as `.name`), a non-negative `int`,
    a non-negative `Duration` (stored as milliseconds), or a catalog error
    code matching `^[A-Z]{2,6}-[0-9]{3}$` (`SAVE-003`); at most 64 characters.
- The dotted-token branch from the reviewed candidate is **removed** (the
  simpler safe variant): a string scalar can no longer be a dotted token, so
  `document.pdf`, `scan.jpg`, `t115.pdf`, `home.user.file`, and
  `max.mustermann` are all discarded. File names and dotted paths are
  explicitly rejected by the catalog-only scalar lane and by the shared
  `CapabilityEvidence` file-extension deny-list on the code/key lanes.
- Dropped by construction: free text, titles, paths, OCR text, field values,
  signature marks, `null`, booleans, doubles, negative numbers/durations,
  nested maps, lists, and byte payloads.
- The class documentation states these three lanes and the fail-closed
  behavior instead of the former claim.
- `@visibleForTesting debugEvents` is a **test-only read accessor** (annotated
  `@visibleForTesting`, returning an unmodifiable list); no production code
  reads it. The `AndroidRasterClient.debugRememberPageSize` precedent is a
  write hook, not an equivalent read accessor; only the test uses the getter.
- **Call sites**: no production code calls `diagnostics.event`; only tests do.
  `AndroidDiagnosticsClient` is constructed in
  `apps/feldexa_app/lib/bootstrap/android_platform_runtime.dart`, and the
  registry only exposes the `DiagnosticsPort`. No caller needed a change. No
  new logs or exports.

exclusion duty, not the historical behavior. The sharp test smuggles a path, a

(`home.user.file`, `max.mustermann`), a 65-character token, nested payloads,

## Residual

- The T099 ledger row stays open until this fix merges; no ledger edit here per
  the brief.
- The event-code namespace allowlist is explicit. A new event namespace is
  dropped fail-closed until this list is extended; no production caller exists
  today.
- The catalog-code check is shape-based, not membership-based (the same house
  convention as `FeldexaException._validateCatalogCode`); an unrelated value
  shaped like `KUNDE-123` would pass. A closed catalog would need a maintained
  code list.
- No emulator run: the client is a pure Dart ring buffer, so the host suite is
  the correct evidence for the filter. This adds no runtime evidence and claims
  none.
- Diagnostics remain on-device; the fix removes content from the buffer rather
  than adding any transmission, logging, or export channel.
