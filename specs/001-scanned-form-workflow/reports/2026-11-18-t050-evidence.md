## 1. Scope

This report covers exactly T050 / issue #50: the new host-VM contract test
`packages/feldexa_recognition/test/suggestion_schema_test.dart` for
`contracts/recognition-output.md` §1 (envelope), §2–§2.1 (suggestion and
forbidden outputs), §4 (failure shape), and the deterministic ordering in
§5.2. It adds the one genuinely required dev dependency (`flutter_test` from
the Flutter SDK) to `packages/feldexa_recognition/pubspec.yaml`. It changes no
production Dart, recognition library, barrel, raster, detector, analysis,
persistence, core, ports, app, Kotlin, Android, ARB, catalog, generated
localization, Gradle, `tasks.md`, checklist, contract, spec, or plan file.

**Branch taken:** a fully self-contained test with test-local map validators.
The optional `packages/feldexa_recognition/lib/src/suggestion_schema.dart`
helper was **not** created because the contract was expressible without one.
`feldexa_core` was not imported: that would require a dependency edit outside
the owned file set, so the `FieldSuggestion`/`SuggestionEvidence`/`FieldType`
shape is mirrored in the test-local fixtures and validators and documented as
intentional duplication. No production envelope type, persistence, analysis,
detector, or schema helper is implemented here.

What this run proves:

- §1 envelope: the exact key set; `schemaVersion == 1`; a canonical lowercase
  UUID `analysisRunId` shared by every page envelope of one run; a 0-based
  `pageIndex` covering each page exactly once; `pageSizePt` equal to the passed
  page display size; the `0/90/180/270` rotation vocabulary; `complete|failed`
  with `failure` present exactly when failed; the four
  `skew|orientation|low_contrast|structure` reasons required exactly when
  `pageUncertain` is true and null otherwise; one envelope per page with no
  duplicate pages; `timings` as non-negative integer `rasterMs`/`ocrMs`/
  `detectMs`; and the `simulated|emulator|device` evidence class.
- §1 canonical projection: a deterministic projection that removes `timings`
  and `evidenceClass` is equal for envelopes differing only in those diagnostic
  fields and unequal for a meaningful change (`rotation`).
- §2 suggestion: `s_p<pageIndex>_<zero-padded ordinal>` with the page token in
  plain decimal, one-based ordinal, canonical four-digit padding, and equality
  to the post-sort position; `pageIndex` equal to the envelope; `rect` inside
  `[0, 0, pageW, pageH]`, positive dimensions, and quantized to 1/8 pt;
  the closed `text|number|date|checkbox|multiline|signature` type vocabulary;
  `confidence` in `0.0 … 1.0` with two decimals; `uncertainty == 1 − confidence`
  with two decimals; `labelText` null or non-empty, trimmed, and at most 200
  characters; `evidence.cues` limited to the §3.1 closed vocabulary (including
  `keyword_<key>` against lexicon v1 only), unique, and in §3.1 declaration
  order; at least one geometric cue; `cueAgreement >= 1`; `skewDegrees` on
  `[-10, +10]`; `contrast ∈ {normal, low}`; and a boolean `ocrUsed` whose
  `false` value excludes OCR-dependent cues.
- §2 conflicts: `conflictsWith` is duplicate-free, never self-referential,
  references existing suggestions in the same page envelope, is symmetric, and
  every referenced pair has `IoU >= 0.5`; the test asserts both candidates
  remain present.
- §2 `resolution`: the closed `unresolved|confirmed|rejected` vocabulary, and
  persisted analysis output may carry only `unresolved`; the audit shape
  (`confirmed`/`rejected`) is accepted only when the validator is explicitly
  told that the output is not persisted analysis output.
- §2.1 forbidden outputs expressible in the schema: no auto-confirm or export
  fields, no persisted confirmed/rejected resolution, and no OCR-only evidence.
  The >12 % printed-ink rule is **not** schema-expressible; the test documents a
  negative fixture, rejects an attempted `inkDensity` field as unknown, and
  records that T051/T052 own ink measurement and detector rejection.
- §4 failure: the four `rasterization|ocr|unsupported_structure|internal`
  categories; required `category`, `messageKey`, `recoverable`, and
  `suggestionCount`; a code-only `REC-<nnn>` message key; a failed page keeps
  its envelope, discards its own partial suggestions, and leaves another
  page's three suggestions intact; `pending` is rejected because cancellation
  is not a failed analysis envelope.
- §5.2 deterministic order: page → rounded `y` → rounded `x` → type ordinal →
  ID, asserted both by a positive sorted fixture and by a reordered-array
  rejection.

What this run never proves:

- No detector logic, raster analysis, OCR, label/type inference, confidence
  model, conflict detector, persistence, logging, encryption, or UI exists in
  this change. The test pins the contract, not a production class. T057 owns
  `FieldSuggestionSet`; T051 owns the raster API; T052–T055 own detectors,
  inference, confidence, and conflicts.
- No detection quality, false-positive/false-negative rate, position accuracy,

  a recognition evaluation and cannot support SC-001/SC-002/SC-004.
- No Android runtime, emulator, device, browser, PDFium, Keystore, protected
  store, MethodChannel, or user journey was executed. The test is host-VM only.
- The >12 % printed-ink rule and §6's center-containment conflict clause are not
  exercised; both are detector-owned. `labelText` being "never logged" is a

- The test-local vocabulary and validators duplicate contract shape from
  `contracts/recognition-output.md` and `packages/feldexa_core/lib/src/model/field.dart`;
