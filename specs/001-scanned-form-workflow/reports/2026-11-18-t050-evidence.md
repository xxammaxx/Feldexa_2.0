**Why the production file exists:** Review A correctly found the first version
self-referential. The contract existed only in a test-local validator, so a
violating production implementation would not have failed the suite. The
dispatch explicitly allowed minimal production type definitions/schema
helpers; this correction adds exactly one pure-Dart schema module and refactors
the test to use it as the only oracle. The optional-file decision from the
first round is therefore reversed deliberately.

**Adoption contract for T057/T058:** T057's `page_analysis.dart`
serializer/deserializer and T058's persistence reader **must** import
`package:feldexa_recognition/src/suggestion_schema.dart` and call
`SuggestionSchema.validateRun` (whole run) or
`SuggestionSchema.validateEnvelope` (one page) as the single validation source.
They must not duplicate these rules in `FieldSuggestionSet` or in a persistence
model. Suggestion sorting uses `SuggestionSchema.sortedSuggestions` /
`compareSuggestions`; canonical determinism input uses
`SuggestionSchema.canonicalProjection` (which excludes `analysisRunId`,
`timings`, and `evidenceClass`) and `canonicalJson`. The package has no
barrel by design, so the `src/` import is the intended adoption path. This
report does not claim that T057/T058 already call it; those files are not yet
implemented.

**Delta-review correction round 2:** both delta reviewers found one precise
assertion gap: the invalid-cue negatives used only non-geometric cues and
asserted only the path. Deleting the vocabulary rule still left the
"no geometric cue" violation at the same path, so those negatives kept
passing and the earlier report's claim that removing any production rule fails
the suite was false. Correction 2 isolates every negative case, asserts exact
finding counts/codes/paths, and adds a 51-mutation per-rule sensitivity matrix.
The claim in this report is now limited to the mutation-tested rules listed in
§5; it is not a blanket claim about every branch.

What this run proves:

- §1 canonicalization: `canonicalProjection` removes `analysisRunId`,
  `timings`, and `evidenceClass` per §5 item 5; `canonicalJson` provides
  sorted-key deterministic JSON. Run-ID-only and diagnostic-only changes
  therefore compare equal and a meaningful change (`rotation`) compares
  unequal. This projection is the determinism projection, not a
  revision-identity hash; no separate run-identity-retaining revision hash
  exists in this module.
- Content-free diagnostics: an unexpected input key is reported at the fixed
  structural marker `<parent>.<unknown-field>` for the envelope, suggestion,
  evidence, failure, rect, and timings objects; no finding path or
  `toString()` contains the supplied key or value. `canonicalJson` errors use
  fixed messages and never echo keys, values, or recursive paths.
- Strict integer types: `schemaVersion` and suggestion `pageIndex` reject
  numerically equal doubles (`1.0`, `0.0`). Envelope `pageIndex`, `rotation`,
  `cueAgreement`, failure `suggestionCount`, and all timings values were
  already strict; integer positives remain valid.
- §1 envelope: exact key set; `schemaVersion` is the integer `1`; canonical
  lowercase UUID `analysisRunId` shared by every page envelope of one run;
  0-based `pageIndex` covering each page exactly once; `pageSizePt` equal to
  the supplied display size; rotation `0/90/180/270`; `complete|failed` with
  `failure` present exactly when failed; `pageUncertain` semantics with one of
  four reasons required when true; non-negative integer timings; and the
  `simulated|emulator|device` evidence class.
- §2 suggestion: `s_p<pageIndex>_<one-based ordinal padded to at least four
  digits>`, plain-decimal page token, canonical padding, and post-sort
  position; `pageIndex` equality; `rect` inside the page display bounds with
  positive dimensions and 1/8-pt quantization; closed field-type vocabulary;
  two-decimal `confidence` in `0.0 … 1.0`; `uncertainty == 1 − confidence`;
  null or trimmed ≤200-character `labelText`; §3.1 cue membership,
  uniqueness, and ascending UTF-16 code-unit order (`String.compareTo` on every
  adjacent pair < 0); at least one geometric cue; `cueAgreement >= 1`;
  `skewDegrees` in `[-10, +10]`; `contrast ∈ {normal, low}`; boolean
  `ocrUsed`; and no OCR-dependent cue when `ocrUsed` is false.
- §2 conflicts: duplicate-free, no self-reference, real same-page references,
  declared symmetry, and §6 qualification. A conflict qualifies when
  `IoU >= 0.5` or when one rect contains the other's center and the Euclidean
  center distance is `<= 4 pt` (inclusive, 1/8-pt rounded). Every declared pair
  must qualify, and every qualifying pair must name the other id from both
  sides; both candidates remain.
- §2 `resolution`: `unresolved|confirmed|rejected`, with persisted output
  restricted to `unresolved`; audit/read models may pass `persisted: false`.
- §2.1 forbidden outputs expressible in the schema: no auto-confirm/export
  fields, no persisted confirmed/rejected state, and no OCR-only evidence.
  The >12 % printed-ink rule is detector-owned and not schema-expressible.
- §4 failure: the four categories; required `category`, `messageKey`,
  `recoverable`, `suggestionCount`; code-only `REC-<nnn>` keys; a failed page
  keeps its envelope, discards its own suggestions, and leaves other pages'
  suggestions present; `pending` is not a failed analysis envelope.
- §5.2 deterministic comparator: page → rounded `y` → rounded `x` → type
  ordinal → ID, directly exposed as `SuggestionSchema.compareSuggestions` and
  `sortedSuggestions`, and enforced for envelope array order.
- The test is no longer self-referential: every positive and negative fixture
  is validated through the production `SuggestionSchema`; the test keeps only
  fixture builders, production-surface wrappers, and path/code expectations.
  There is no test-local validator or second vocabulary oracle.
- Every negative fixture is isolated: `_expectViolation` asserts the exact
  number of findings at the expected path, the exact stable code(s), and that
  no finding exists at any other path. Intentional multi-rule cases are
  enumerated in §5; the invalid-cue fixtures include `underline` and are sorted
  so the closed vocabulary (`value`) is the only finding.
- A 51-case mutation matrix disabled one production rule at a time and every
  case failed at least one focused test; the source was restored byte-for-byte
  after each mutation (§5). The mutation script was scratch-only and is not
  committed.

**Review-correction 3 rules (Commit A `72f89b1`).**

1. **Cue sortedness (Review B).** `contracts/recognition-output.md` §2 line 81
   requires `evidence.cues` to be "sorted, unique". The validator now requires
   ascending UTF-16 code-unit order: each cue compared with the next using Dart
   `String.compareTo`, valid only when every adjacent pair satisfies
   `compareTo(...) < 0`. For the ASCII §3.1 tokens this is ASCII lexicographic
   order. A violation uses the existing `order` code at
   `<suggestionPath>.evidence.cues`. Uniqueness keeps the existing `duplicate`
   code and behavior; a duplicated list is also non-ascending and may carry
   both `duplicate` and `order`.
2. **§6 conflict completeness (Review A).** One shared predicate decides
   qualification: two rects conflict when `IoU >= 0.5` **or** when one rect
   contains the other's center and their Euclidean center distance is
   `<= 4 pt`. Both thresholds are inclusive (`IoU == 0.5` and distance
   `== 4.0 pt` qualify), center containment is inclusive of the rect boundary,
   and each coordinate is rounded to 1/8 pt with `_roundToEighth` before
   comparison. A declared conflict id pair must qualify under either clause;
   otherwise `overlap` is emitted at `<suggestionPath>.conflictsWith`.
   After individual suggestion validation, a pairwise pass over structurally
   valid suggestions in envelope order emits `symmetry` at a suggestion's
   `<suggestionPath>.conflictsWith` for each missing direction of a qualifying
   pair. A fully undeclared qualifying pair yields two findings (one per side);
   a declared one-sided pair yields the existing declared-symmetry finding plus
   the missing reverse finding. Non-qualifying pairs produce no finding.
3. **Retained non-rule:** `uncertaintyReason` may be a valid reason when
   `pageUncertain` is false; it is required and vocabulary-restricted only when
   `pageUncertain` is true.
4. **Documented T051 follow-up:** the
   `// ignore_for_file: depend_on_referenced_packages` line and its stale
   "remove once T050's dev_dependency is merged" sentence were removed from
   `packages/feldexa_recognition/test/raster_test.dart`. `flutter analyze
   --no-pub` remains clean, and no other T051 file changed.

## 7. Limitations

- `NONE` only: host-VM schema assertions, not runtime, detector, corpus,
  acceptance, or product-completion evidence.
- The production schema exists but has **no consumer yet**. T057 must adopt it
  in `page_analysis.dart`; T058 must adopt it in persistence. Until then, a
  production serializer could still bypass it, although the tests now fail if
  the schema rules themselves are weakened.
- No detection logic, ink measurement, OCR, rasterization, persistence,
  encryption, UI, or logging behavior is implemented or verified.
- No Android runtime, emulator, device, browser/Chrome, PDFium, Keystore,
  protected store, MethodChannel, or real document was used.
- Synthetic fixtures contain no real document content, titles, paths, or URIs.
  No personal data, corpus, or evaluation result is present.
- Diagnostics are content-free by construction: an unexpected key collapses to
  the fixed `<parent>.<unknown-field>` marker. A finding therefore does not
  reveal which unexpected key was present or how many distinct unexpected keys
  an object carried; it identifies only the parent structure and the stable
  `unexpected` code. The canonical-JSON regression guards the fixed-message
  behavior; at the starting candidate its recursive path appended list indexes
  only, so it was not a RED privacy test.
- Strict integer acceptance is a wire-shape rule only. A serializer or decoder
  that turns JSON `1.0` into a Dart `int` would bypass the distinction; no
  producer or serializer is implemented here, and T057/T058 must preserve the
  wire types when adopting the schema.
- `canonicalProjection` is the §5 item 5 determinism projection, not a
  revision-identity hash. No separate run-identity-retaining revision hash
  exists in this module; T057/T058 must define any revision-identity semantics
  separately and must not infer them from this projection.
- Cue sortedness is enforced by the validator from synthetic cue lists only;
  no detector implementation is exercised. `pageUncertain == false` may carry a
  valid `uncertaintyReason`.
- The §6 conflict predicate and completeness pass are validated from synthetic
  wire rects only; detection, duplicate collapsing, conflict badges, and
  resolution behavior remain out of scope.
- `labelText` privacy ("never logged") and the >12 % ink rule remain
  production/detector obligations outside this schema test.
- The test still contains contract-derived vocabulary lists and descriptive
  path expectations, but it is not a validator: all verdicts come from
  `SuggestionSchema`.
- The mutation matrix is a bounded sensitivity check, not exhaustive branch
  coverage. The untested rules are listed in §5 and must not be described as
  mutation-verified.
- The mutation harness was scratch-only and is not committed; its exact
  mutations are summarized in the §5 matrix. Reproducing it requires recreating
  the listed one-line mutations.
- `tasks.md` is unchanged; T050 remains unchecked for the integrator. No
  independent review or approval is claimed. T051's production files and its
  worktree were not touched; correction 3 removed only the documented
  `raster_test.dart` suppression line, and correction 4 leaves
  `raster_test.dart` unchanged.
