# Synthetic fixture generator (T009)

Deterministic generator for the `SIMULATED` Web development fixtures declared
by `specs/001-scanned-form-workflow/plan.md` §Project Structure, research
decisions D-16/D-18, and `quickstart.md` §2.

```bash
dart run tools/corpus/synthetic/generate.dart          # write files
dart run tools/corpus/synthetic/generate.dart --check  # verify byte-for-byte
dart run tools/corpus/synthetic/generate.dart --help
```

Exit codes: `0` success/current, `1` drift or I/O error, `2` usage error.
The tool needs no package dependencies beyond `dart:io`, `dart:convert`, and
`dart:typed_data`, so it also runs offline with a bare Dart SDK.

## Files

| File | Responsibility |
| --- | --- |
| `generate.dart` | CLI, catalog/OCR JSON rendering, write and `--check` modes, determinism assertions. |
| `fixtures.dart` | All fictional form layouts, field/OCR declarations, and ground truth. |
| `pdf_writer.dart` | Deterministic PDF 1.7 writer; display-space geometry and rotation transforms. |
| `crypto.dart` | Local SHA-256 (integrity pins), plus MD5/RC4 for the legacy protected fixture. |

Generated outputs:

- `apps/feldexa_app/assets/fixtures/catalog.json` (canonical, **not** a
  Flutter asset)
- `apps/feldexa_app/assets/fixtures/sf-*.pdf`
- `apps/feldexa_app/assets/fixtures/sf-*.expected-ocr.json`
- `apps/feldexa_app/web/fixtures/...` (byte-identical Web delivery mirror,
  served at `/fixtures/...`)
- `tools/corpus/synthetic/sf-*.pdf` (byte-identical copies for `adb push`)

The canonical files are the source of truth. The integrity test requires all
three copies to match; `--check` verifies all 31 generated files. Because the
canonical directory is not declared under `flutter.assets`, no fixture bytes
can enter a production Android APK/AAB.

## Web runtime check

`test_web_fixtures.sh` starts `serve_web_fixtures.dart` over a local
`build/web` tree and runs `apps/feldexa_app/test/web_fixtures_browser_test.dart`
in Chrome with `flutter test --platform chrome`. The test fetches every
catalog entry, re-hashes the PDFs with an independent SHA-256, checks page
markers and OCR block counts, and repeats a fetch to prove byte determinism.
It is `SIMULATED` browser evidence for fixture delivery only, not an editor
journey or Android evidence.

## Determinism rules

- Base-14 Helvetica (`/F1`, `/F2`) with `/WinAnsiEncoding`; non-ASCII bytes are
  octal-escaped so unencrypted content streams stay valid 7-bit ASCII.
- Uncompressed content streams; fixed object numbering; fixed `/ID`; fixed
  generation date; no `/CreationDate`, `/ModDate`, `/Producer`, or `/Creator`.
- No randomness, wall clock, locale-dependent formatting, directory iteration,
  or network input.
- The same layout declarations produce the PDF drawing, the expected OCR
  blocks, and the ground-truth rectangles, so the three cannot drift.
- `_verifyDeterminism` builds each document twice before writing and rejects
  any byte difference.

## Geometry

All layout coordinates are page **display points** (top-left origin, y down).
`pdf_writer.dart` converts to PDF user space with the inverse of
`contracts/coordinates-and-geometry.md` §2, including text matrices for
`/Rotate` 0/90/180/270. The catalog records display dimensions (which swap for
90/270 rotations), so consumers never re-derive rotation.

## Protected fixture

`crypto.dart` implements MD5 and RC4 only to emit a genuine Standard Security
Handler revision 2 PDF:

- non-empty user password `feldexa-user`, fixed owner password `feldexa-owner`;
- `/V 1 /R 2 /Length 40`, fixed `/P -44`;
- per-object RC4 stream keys from the file key and object/generation numbers.

Verified independently with Poppler: `pdfinfo` reports `Encrypted: yes ...
algorithm:RC4`; `pdftotext` extracts with `-upw feldexa-user` or
`-opw feldexa-owner` and rejects empty/wrong passwords. The
fixture exists solely to prove `IMP-001` rejection and is never used for
product data.

## Scope boundary

T009 produces development fixtures only. It does not create the frozen real
corpus or `tools/corpus/manifest.json` (T033), the fixture loader (T011), the
simulated adapters (T028), the browser tests (T047/T062/T072/T087/T128), or
the Android import tests (T046). Those tasks may consume this catalog; any
change to generated bytes must follow the change policy in
`apps/feldexa_app/assets/fixtures/PROVENANCE.md`.
