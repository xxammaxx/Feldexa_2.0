# German OCR reference suite (T263, issue #263)

Additive synthetic reference for German special characters and Unicode
behaviour on the real Android ML Kit OCR path. It does **not** replace or
re-freeze the real corpus (`corpus-1.0.0`), and it does not change any existing
synthetic fixture byte.

| Item | Value |
| --- | --- |
| Fixture | `sf-005` in the dev catalogue (`fixtures-1.1.0`) |
| Suite id | `de-ocr-1.0.0` |
| Generated by | `dart run tools/corpus/synthetic/generate.dart` |
| Byte check | `dart run tools/corpus/synthetic/generate.dart --check` |
| Suite verification | `bash tools/corpus/de-ocr/verify.sh` |
| Ground truth | `tools/corpus/de-ocr/reference-de.ground-truth.json` |
| Qualification scorer | `dart run tools/metrics/de_ocr_qualification.dart` |
| Scan variants | `python3 tools/corpus/de-ocr/make_variants.py` |
| Emulator driver | `tools/android/t263_drive_de_ocr.sh` |

## Why a separate writer

The shared fixture writer (`../synthetic/pdf_writer.dart`) draws with base-14
Helvetica and `/WinAnsiEncoding`, which has no code point for U+1E9E (LATIN
CAPITAL LETTER SHARP S). Printing `ẞ` therefore needs an embedded TrueType
font. `ttf_embed.dart` embeds the project-bundled Noto Sans Regular
(`apps/feldexa_app/assets/fonts/NotoSans-Regular.ttf`, SIL OFL 1.1) verbatim as
a Type0/CIDFontType2 font with `/Identity-H` and a `ToUnicode` CMap:

* every printed code point is resolved through the font's own `cmap`, so glyph
  coverage is proven rather than assumed (the generator fails otherwise);
* the text layer is character-faithful, which makes the PDF text layer usable
  as an independent control path;
* output stays byte-deterministic (fixed object order, no timestamps, fixed
  `/ID`, no subsetting).

The raster is visually verified after generation; see the T263 evidence report
for the rendered page and the glyph inventory.

## Ground truth

`reference-de.ground-truth.json` is emitted from the same declaration that
draws the PDF, so the two cannot drift. It contains:

* `lines[]` — one entry per printed line: verbatim NFC text, its NFD spelling,
  the display-space rectangle, the line role, whether the line is critical for
  the clean baseline, and the special characters it carries;
* `fields[]` — the declared label/field roles for the label-takeover page;
* `requiredCharacters[]` / `requiredAuthorityTerms[]` — the inventory the issue
  requires (Ä Ö Ü ä ö ü ß ẞ € ² ³; Straße, Größe, Gebühr, Geschäftszeichen,
  Staatsangehörigkeit, Überweisung, Erklärung, Anträge);
* `metricsPolicy` — the raw-text rule (no normalization), the semantic matching
  aliases (NFC/NFD, case, ae/oe/ue/ss, matching only), the no-silent-correction
  list, and the evidence-class definitions;
* `variants[]` — the pre-declared clean and degraded variants with their
  evidence class and thresholds, committed **before** the first scored run.

## Evidence classes

| Class | Meaning |
| --- | --- |
| `EMULATOR` | Production raster port (PDFium/pdfrx) plus production bundled ML Kit OCR on the emulator; the only class that satisfies the clean-reference device gate |
| `EMULATOR_INJECTED_RASTER` | Production ML Kit OCR and production pipeline over a raster degraded on the host (scan simulation); never claimed as clean production-path evidence |
| `SIMULATED` | Declared fixture expectations or host-only output; never device evidence |
| `TEXT_LAYER` | PDF text layer through Poppler; control path for the printed code points only |

An `UNRESOLVED` case is reported as unresolved and is never counted as an
accuracy PASS.

## Reproducing

```bash
# 1. regenerate and byte-check the fixture and its ground truth
dart run tools/corpus/synthetic/generate.dart --check
bash tools/corpus/de-ocr/verify.sh

# 2. control path: text layer (no device)
python3 tools/metrics/build_text_layer_run.py \
  --pdf apps/feldexa_app/assets/fixtures/sf-005.pdf \
  --ground-truth tools/corpus/de-ocr/reference-de.ground-truth.json \
  --output /tmp/t263-text-layer.json
dart run tools/metrics/de_ocr_qualification.dart \
  --run /tmp/t263-text-layer.json --output /tmp/t263-text-layer-report.json

# 3. real emulator run (exclusive emulator window required)
tools/android/t263_drive_de_ocr.sh
```

## Device binding and the `NOT_RUN` gate

`tools/android/t263_drive_de_ocr.sh` binds the device from the ADB transport
table: no supervisor layer is asked for an allocation and no allocation file is
read, so a run is reproducible on any host with a booted AVD. The gate fails
closed, in this order:

1. `adb devices` is read once into the transport table; every listed transport
   counts as attached, whatever its state.
2. Exactly one attached transport must match `^emulator-[0-9]+$`.
3. That emulator must equal the requested serial (`T263_SERIAL`, default
   `emulator-5554`).
4. The requested serial itself must match `^emulator-[0-9]+$`. The project
   handset is attached over WLAN and is reserved for the release acceptance, so
   it must never be addressed — not even when it is the only attached device.
   No device command runs before this check, and `adb_shell` refuses to run until
   the gate has bound the serial, which also covers the cleanup trap.
5. AVD (`ro.boot.qemu.avd_name`), API level (`ro.build.version.sdk`, 35) and a
   completed boot (`sys.boot_completed`) are then verified.

A gate failure prints `T263 EMULATOR NOT_RUN: <reason>` and exits `2`. That is
not a measurement failure: no evidence class is produced and no run file is
written. A passing gate records two committed files — `device-binding.txt`
(transport counts by class, `addressed_serial`,
`non_emulator_transports_addressed=none`) and `device-identity.txt` (serial, AVD,
API, ABI, fingerprint, `boot_completed`, `qemu`, screen and memory). Both are
committed evidence, so they carry counts instead of transport names and no
absolute host path.

Dry-probing the gate needs no emulator. Point `T263_ADB` at a stub that answers
`devices` from a prepared table and `T263_RUN_DIR`/`T263_EVIDENCE_DIR` at
throwaway directories, then run the driver. The cases that must end in
`NOT_RUN` are: two emulators, one emulator with a foreign serial, a physical
serial (`adb-RFCW80SMY4J-…`), and an emulator plus a wireless transport while the
physical serial is requested. One emulator plus a wireless transport with the
emulator requested must pass the gate and record
`all_attached_transports_count=2`, `emulator_transports=1`,
`non_emulator_transports=1`.

Only synthetic, rights-cleared content is used. No private form, personal data,
or third-party form content is included, and the generated documents carry a
visible synthetic marker on every page.
