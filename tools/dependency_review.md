### 7.2 OD-T003-1 resolution: BouncyCastle 1.72 → 1.87

`pdfbox-android 2.0.27.0`'s POM pins `bcprov-jdk15to18`, `bcpkix-jdk15to18` and `bcutil-jdk15to18` to `1.72`. OSV reports 12 advisories for 1.72 across `bcprov` (10) and `bcpkix` (2); the highest fixed-version floor is 1.85, and 1.87 is the latest published line. The advisories include GHSA-9pwp-9qqc-pr26 (CVE-2026-8763, name-constraint bypass), GHSA-qp49-qgx5-5m26 (CVE-2026-13506, ASN.1 nesting-depth), GHSA-p93r-85wp-75v3 (CVE-2026-5598, timing), GHSA-574f-3g2m-x479 (CVE-2025-14813, GOST), GHSA-8xfc-gm6g-vgpv (CVE-2024-29857), GHSA-4h8f-2wvx-gg5w (CVE-2024-34447), GHSA-v435-xc8x-wvr9 (CVE-2024-30171), GHSA-67mf-3cr5-8w23 (CVE-2025-8885), GHSA-hr8g-6v94-x4m9 (CVE-2023-33201), GHSA-wjxj-5m7g-mg7q (CVE-2023-33202), GHSA-4cx2-fc23-5wg6 (CVE-2025-8916) and GHSA-wg6q-6289-32hp (CVE-2026-5588).

**Applicability (not an exploit claim).** PDFBox 2.0.27's only BouncyCastle imports are in `PublicKeySecurityHandler` and `SecurityProvider`, used for certificate/public-key-encrypted PDFs (CMS enveloped data). Feldexa's planned path rejects encrypted inputs and does not use certificate signatures; the app's own encryption is Android Keystore AES-256-GCM. The advisories are therefore not asserted to be exploitable in Feldexa. The override removes the listed version as defense-in-depth and to satisfy D-19's CVE-review obligation; it does not claim a Feldexa incident.

**Chosen option (implemented).** Pin `pdfbox-android 2.0.27.0` and override the three `jdk15to18` BC modules to `1.87` in `apps/feldexa_app/android/app/build.gradle.kts` using a Gradle `constraints` block plus a `resolutionStrategy.eachDependency` rule. `1.87` is the latest published line, is OSV-clean, uses the same Bouncy Castle Licence, and targets Java 5+ bytecode suitable for Android. Alternatives rejected:

- **Upstream PDFBox 2.0.37**: not Android-compatible; `jdeps` finds 59 `java.desktop`/AWT references and Android has no `java.desktop`.
- **Newer pdfbox-android**: none published. Maven Central's latest is `2.0.27.0` (2023-01-02); the GitHub repository's latest release is `v2.0.27.0` (last push 2024-03-18).
- **Exclude BouncyCastle**: would break class availability for PDFBox's CMS path; not chosen.
- **Commercial/alternative PDF writer**: licensing or plan change; not a T003 package decision.

**Evidence.**

- JVM regression: PDFBox 2.0.27 public-key certificate encryption and decryption succeeded with both BC 1.87 and BC 1.72; output `BC_PDFBOX_TEST_OK pages=1 encryptedBytes=1916 decryptedBytes=854` with the expected text. This exercises the same BC classes PDFBox uses.
- Gradle `dependencyInsight` in the real app: `org.bouncycastle:bcprov-jdk15to18:1.72 -> 1.87`, "Selected by rule" and "By constraint"; `bcpkix`/`bcutil` also resolve to `1.87`.
- Scratch Android app (AGP 9.1.0, compileSdk 36): `assembleDebug` succeeded, APK 8.1 MB, and `dexdump` found BC 1.87-only classes `Lorg/bouncycastle/pqc/crypto/sqisign/SQIsignSigner;` and `Lorg/bouncycastle/pqc/crypto/xwing/XWingKEMGenerator;` plus `Lorg/bouncycastle/cms/CMSEnvelopedData;` and `Lcom/tom_roush/pdfbox/pdmodel/PDDocument;`.
- Real app: `flutter build apk --debug --target-platform android-x64` succeeded; APK 118 MB (debug, multi-ABI); same BC 1.87-only classes and PDFBox present.
- BC jar SHA-256 values match Maven Central `.sha256` files; BC 1.87 `Implementation-Version: 1.87.0`.

**Residual risk (C-T003-10).** PDFBox-Android `2.0.27.0` is old (tracks upstream 2.0.27 while upstream is 2.0.37) and has no maintained Android port update. BC 1.87 compatibility was proven for the BC path PDFBox actually uses (public-key CMS), not every BC API. T039/T143 must run PDFBox text/font/export/encryption regression tests, and the BC/PDFBox advisory scan must be repeated there and before release. Any BC version change requires a new D-19 review.
